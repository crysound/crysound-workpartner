# 兆华记忆

`@crysound/memory` 在市场和插件清单中显示为“兆华记忆”，设置菜单和页面中简称“记忆”。这是工作伙伴的独立记忆插件，不修改 dsh 本体。0.1.1 重做原生设置页，预装清单固定该版本；须经界面过目、市场审批和发布后再由伙伴助理部署。主对话模型从用户本轮陈述中主动保存稳定的偏好、身份和长期项目事实；不增加后台摘要模型调用，不下载嵌入模型，不接向量库或新外部服务。自动提取由主模型遵循工具说明完成，不保证每个事实都会被提取。

## 使用

通过宿主支持的插件入口安装固定版本的包后，设置中出现“记忆”。页面说明：“伙伴记住的你的工作和偏好，只用于你自己的对话，同事看不到。”网页版和桌面版各存一份，目前不同步。是否经正式网关正确隔离须由伙伴助理用 A/B 账号验收，不能把本地目录隔离测试当正式验收。

“使用记忆”默认开启，状态存在本人的数据库。关闭后新会话不注入任何事实，模型保存工具返回“记忆已关闭”；已有条目保留，可在页面整理，重新开启恢复召回。“添加一条”和逐条“编辑”支持类别、标题和内容；每条显示更新时间及来源（对话中记下 / 手动添加 / 页面修改），悬停时间可查看创建和更新时间。删除单条和“清空全部”均先确认，清空使用一个事务。页面操作与模型保存共用校验、版本检查与拒存规则。

默认最多 50 条，每条标题最多 40 字、内容最多 240 字。模型召回 JSON 包含全部事实、随机编号、更新日期（UTC 年月日；页面时间按浏览器时区）、开关和版本，总量不超过 6000 个 JavaScript 字符；固定操作说明及用量说明另计，字符不是 token。数量与预算可在 profile 配置 `maxMemories`（1–200）、`recallChars`（512–24000）。页面平时只显示“已记 N 条”，超过条数或召回预算的 80% 才提示上限。召回预算包含编号、日期等序列化开销，不等同于记忆正文的字数，因此不在页面显示为“已用字数”；空库显示“已记 0 条”。模型注入仍保留完整预算用量；存储会按两项中先达到的上限拒绝超额写入，不自动删除旧条目。降低预算导致已有事实超额时加载明确失败，应先用原预算整理。

新条目使用随机编号，`crysound_memory_save` 带 `id` 更新原条目，可改标题而不换编号。用量达到任一上限的 80% 时，模型应先提出具体合并或删除方案，用户同意后才能带 `confirmed=true`、`removeIds` 和 `updates` 一次整理并保存：删除旧条目、更新合并目标、保存新事实均在单个事务内，校验、编号、版本或预算任一步失败全部回滚。用户确认由模型遵循对话和工具说明完成；布尔参数不是独立的人工审批凭据。没有合适方案时请用户选择或在页面整理。

成功工具卡片显示“已记住：<标题>（可在 设置 › 记忆 中查看或删除）”，仅从已提交的结果生成；拒存卡片不回显原输入。用户说“这次对话别记”后，模型应在本会话后续轮次停止调用保存工具，直到用户明确恢复；这依赖主模型遵循会话指令，不是持久化的总开关，也不新增会话状态数据库。

## 数据与安全

唯一长期记忆源为 `$DSH_HOME/crysound-memory/memory.sqlite`，未设置 DSH_HOME 时使用 `~/.dsh`；不会探测或写入其他项目、全局指令文件、每日工作日志。网页版由每人的持久化挂载区隔离，同一人不同工作区共用记忆。桌面版在本机 DSH home 独立保存，暂不跨端同步。Node 24 自带 SQLite，无额外运行时依赖或原生模块安装。数据库文件权限为 600，目录新建时为 700。

SQLite 事务串行处理并发写入，读写携带版本，冲突明确返回失败；旧版本的保存不能覆盖新事实或复活刚删除的事实。删除使用 `secure_delete`，不写含原文的墓碑、自动备份或删除日志，不另起后台任务从旧聊天重新提取。每轮重读当前记忆，记录在宿主系统提示词快照中。原会话中的历史工具输出、模型请求和既有备份仍保留原文；这不是聊天记录清除功能，旧会话中已出现的信息也不可能从模型已见的历史里撤回。

提示词要求不记健康状况、宗教、政治立场、对同事的评价或议论、凭据及一次性内容。写入边界拒绝密码、令牌等中英文标签、常见密钥格式、连续 18 位身份证号（允许末位 X）和 16–19 位银行卡号，不依赖校验和；无法识别完全没有标签、也不具备已知格式的任意秘密。存储仅供个人事实使用，不应当作密码管理器。记忆以 JSON 数据呈现且明确不是指令；仍不能保证主模型绝对不受恶意记忆影响。

管理接口沿用 `webStartup.trustedHosts` 及监听地址，校验 Host、Origin、Fetch Metadata、方法、请求体大小和版本。不新加授权域名，不绕开飞书身份网关；测试入口能打开不代表正式公司网关已验收。

## 备份与恢复验收

存储显式设置 `PRAGMA journal_mode=DELETE`，**不使用 WAL**。事务期间仍可能出现回滚日志；不能把“没有 WAL”当成运行中直接复制文件必定一致的保证。

仓库镜像设置 `DSH_HOME=/data/.dsh`，每人数据目录挂载到 `/data`，因此记忆位于每人数据根下的 `.dsh/crysound-memory/memory.sqlite`。已查阅的现有每日 restic 备份脚本包含整个 users 目录，只排除依赖与缓存目录，不排除此文件；现有首次备份日志也列出了 users。这个结论仅确认脚本覆盖规则，插件尚未装入正式备份，未确认线上当前脚本或归档中已有该文件。现有脚本直接读取运行中的文件，没有 SQLite 一致性快照步骤，因此备份一致性和本插件恢复仍待实测。

伙伴助理在测试账号验收一次：页面保存合成事实并记录条数、内容及版本 → 通过 SQLite backup API 取得一致副本，或在获准的隔离测试进程停止写入后让现有备份收录完整数据库 → 从该次备份恢复到另一个空的隔离个人数据目录（不覆盖正式目录） → 核对属主、目录 700 和文件 600，执行 `PRAGMA integrity_check` → 用同版本插件启动，确认页面能看到原记忆、条数和内容一致，且新会话召回相同事实。若用 SQLite backup API，须确认副本实际进入现有备份，并从归档恢复该副本，不能只恢复本地副本代替“备份 → 恢复”。验收记录应写明快照、恢复来源、实际 Node/插件版本和结果；本 PR 不修改正式备份任务，不把这项未验收说成通过。

## 未发布格式与运行时升级

格式版本仍为 1，增加个人开关、创建/更新时间与来源，替换标题哈希为随机编号。插件尚未预装，不提供旧试验库迁移；旧试验库不能直接载入新代码，须由环境负责人确认仅含合成数据后重建，不自动清空未知数据库。

## 升级 dsh / 升级 Node 镜像时复查

- Node 内置 `node:sqlite` 仍是实验性接口；升级 dsh 或 Node 镜像时，重跑存储、HTTP 管理、真实页面删除及备份恢复检查，不增加兼容层。仓库 `crysound/web/Dockerfile` 固定的是 `node:24-bookworm-slim`（主版本 24，未锁补丁或摘要），已完成隔离实测的运行时为 Node **24.22.2** / dsh **0.2.2-rc.1**；每次重建可能取得不同 Node 补丁，伙伴助理应记录实际 `node --version` 后再验收。桌面版实际内置 Node 仍待目标平台确认。

## 检查与交付

轻量检查：Node 24 执行 `node --check index.mjs`、`node --check store.mjs`、`node --check panel.mjs`、`node --check client.js` 和 `node --test tests/*.test.mjs`。测试覆盖开关持久化、编号更新及来源时间、单条和清空后原文移除、旧版本拒写、满额合并与中途失败回滚、凭据及证件/银行卡拒存、独立用户目录和全部真实 HTTP 管理接口。历史真实模型会话保留于评估目录；新版会话与行为证据见[改进验收记录](../memory-evaluation/IMPROVEMENTS.md)，含新版按编号更新的无密钥回放。单独发布的运行包不包含测试及评估资料。

0.1.0 的初版界面和存储结构已获分诊确认，沿用中文管理页和分条 SQLite。早期隔离实测步骤见 [TRIAL.md](../memory-evaluation/TRIAL.md)，候选评估及真实证据见 [评估目录](../memory-evaluation/README.md)。0.1.1 的部署见下文；页面复查不代替正式网关身份隔离、桌面版、备份恢复、长期并发和提取率的验收，相关结论须以伙伴助理的部署验收记录为准。

## 0.1.1 设置页与截图复查

页面使用 dsh 原生 Button、Switch、Input、Menu、Modal 和图标，沿用通用设置的间距与主题变量；插件只提供布局。页面打开、窗口重新获得焦点或标签页恢复可见时自动读取，取消挂载时终止读取；打开编辑或确认框时保留当前版本和草稿，关闭后再刷新。读取错误与操作失败提示分别保存，自动刷新成功不会清掉尚待用户处理的操作失败提示。并发写入仍拒绝旧版本，不自动重试覆盖。删除说明只在确认框内出现，清空仅在有条目时显示于列表底部。跨端不同步说明位于页底。市场插件移除隐藏窄屏设置导航的旧样式，由原生设置壳负责横向导航。

浏览器复查脚本为 `tests/settings-browser.mjs`。先通过环境已配置的持久浏览器入口新建自己的标签页，再用 Node 24 运行 `CDP_TAB=<标签页> node tests/settings-browser.mjs <证据目录>`。脚本沿用该会话的真实原生设置壳，在本人标签页中替换本分支的记忆模块和品牌文件，将所有记忆接口请求截获并交给临时 SQLite 与真实 HTTP 管理接口；不修改正式记忆、语言或主题偏好，不调用模型，不发布插件。它验证开关、类型选择、增改删清空、取消、自动刷新、并发冲突，以及浅深色与宽窄屏的空状态、三条记忆、接近上限和两种确认框。深色通过当前页面的原生主题标记切换，截图裁剪到设置窗口，不包含账号或聊天内容。证据不代替安装发布后的整体验收。

部署：从测试发布账号提交 `@crysound/memory@0.1.1`，界面截图过目并在市场审批后更新共享预装清单。品牌层与市场图标补丁随网页版镜像、桌面版运行时更新；网页版按 CRYSOUND.md 由伙伴助理在用户空闲时更新。已有 0.1.0 数据格式不变。上线后确认插件版本、预装版本及设置页功能；Mac/Windows 桌面版仍需各自验收。不在本轮执行发布、审批或线上容器操作。
