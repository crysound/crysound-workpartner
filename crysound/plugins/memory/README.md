# 兆华记忆

`@crysound/memory` 是工作伙伴的独立记忆插件，不修改 dsh 本体，已在公司预装清单中。主对话模型从用户本轮陈述中主动保存稳定的偏好、身份和长期项目事实；本草稿增加主对话之外的后台补记，经现有公司模型网关，不下载嵌入模型、不接向量库或新外部服务。主对话与后台均不保证每个事实都会被提取；本轮真实配对未见提取增益，未达交付条件。

## 使用

通过宿主支持的插件入口安装固定版本的包后，设置中出现“记忆”。页面说明：“这是你本人的记忆，只用于你自己的对话；同事看不到，也不会出现在别人的对话里。”网页版和桌面版各存一份，目前不同步。是否经正式网关正确隔离须由伙伴助理用 A/B 账号验收，不能把本地目录隔离测试当正式验收。

“使用记忆”默认开启，状态存在本人的数据库。关闭后新会话不注入任何事实，模型保存工具返回“个人记忆已关闭”；已有条目保留，可在页面整理，重新开启恢复召回。“添加一条”和逐条“编辑”支持类别、标题和内容；每条显示更新时间及来源（对话中记下 / 手动添加 / 页面修改），悬停时间可查看创建和更新时间。删除单条和“清空全部”均先确认，清空使用一个事务。页面操作与模型保存共用校验、版本检查与拒存规则。

默认最多 50 条，每条标题最多 40 字、内容最多 240 字。模型召回 JSON 包含全部事实、随机编号、更新日期（UTC 年月日；页面时间按浏览器时区）、开关和版本，总量不超过 6000 个 JavaScript 字符；固定操作说明及用量说明另计，字符不是 token。数量与预算可在 profile 配置 `maxMemories`（1–200）、`recallChars`（512–24000）。页面与注入开头均显示“已用 N/50 条、M/6000 字”；存储会按两项中先达到的上限拒绝超额写入，不自动删除旧条目。降低预算导致已有事实超额时加载明确失败，应先用原预算整理。

新条目使用随机编号，`crysound_memory_save` 带 `id` 更新原条目，可改标题而不换编号。用量达到任一上限的 80% 时，模型应先提出具体合并或删除方案，用户同意后才能带 `confirmed=true`、`removeIds` 和 `updates` 一次整理并保存：删除旧条目、更新合并目标、保存新事实均在单个事务内，校验、编号、版本或预算任一步失败全部回滚。用户确认由模型遵循对话和工具说明完成；布尔参数不是独立的人工审批凭据。没有合适方案时请用户选择或在页面整理。

稳定偏好、纠正和长期背景第一次出现就按指引保存；中文信号须结合语义，临时状态、一次性要求和进度不记，内容写成陈述句。保存成功后，在本条回复下方显示小字“已记住：<标题>”，仅从已提交的结果生成；伙伴无需口头重复。回执带已提交条目的编号，更新同一条时仍定位同一编号；旧会话没有新版元数据时保留原卡片，拒存卡片不回显原输入。

当前 dsh 的工具卡片支持可点击组件，也提供回复末尾扩展位，但没有供插件直接打开并选中原生设置页的公开动作。本版点击回执在原页面打开同一个记忆管理组件的弹窗，并滚动、聚焦目标条目；已删除的条目显示说明，不恢复内容。这是待界面分诊确认的替代方案，不能当作“已直达原生设置页”验收。源码和预装版本拟升级为 0.1.2，避开设置页改版 PR #89 使用的 0.1.1；两单均修改 client.js，交付前须合并最新 main、保留新版页面样式与定位能力，再按[本单验收记录](../memory-evaluation/FIRST-MENTION.md)复查。用户说“这次对话别记”后，模型应在本会话后续轮次停止调用保存工具，直到用户明确恢复；这依赖主模型遵循会话指令，不是持久化的总开关，也不新增会话状态数据库。

## 数据与安全

唯一长期记忆源为 `$DSH_HOME/crysound-memory/memory.sqlite`，未设置 DSH_HOME 时使用 `~/.dsh`；不会探测或写入其他项目、全局指令文件、每日工作日志。网页版由每人的持久化挂载区隔离，同一人不同工作区共用个人记忆。桌面版在本机 DSH home 独立保存，暂不跨端同步。Node 24 自带 SQLite，无额外运行时依赖或原生模块安装。数据库文件权限为 600，目录新建时为 700。

SQLite 事务串行处理并发写入，读写携带版本，冲突明确返回失败；旧版本的保存不能覆盖新事实或复活刚删除的事实。删除使用 `secure_delete`，不写含原文的墓碑、自动备份或删除日志，手动删除、清空或撤销同时推进取材时间边界，后台不会从此前的聊天重新提取；旧聊天记录本身保留。每轮重读当前记忆，记录在宿主系统提示词快照中。原会话中的历史工具输出、模型请求和既有备份仍保留原文；这不是聊天记录清除功能，旧会话中已出现的信息也不可能从模型已见的历史里撤回。

提示词要求不记健康状况、宗教、政治立场、对同事的评价或议论、凭据及一次性内容。写入边界拒绝密码、令牌等中英文标签、常见密钥格式、连续 18 位身份证号（允许末位 X）和 16–19 位银行卡号，不依赖校验和；无法识别完全没有标签、也不具备已知格式的任意秘密。存储仅供个人事实使用，不应当作密码管理器。记忆以 JSON 数据呈现且明确不是指令；仍不能保证主模型绝对不受恶意记忆影响。

管理接口沿用 `webStartup.trustedHosts` 及监听地址，校验 Host、Origin、Fetch Metadata、方法、请求体大小和版本。不新加授权域名，不绕开飞书身份网关；测试入口能打开不代表正式公司网关已验收。

## 备份与恢复验收

存储显式设置 `PRAGMA journal_mode=DELETE`，**不使用 WAL**。事务期间仍可能出现回滚日志；不能把“没有 WAL”当成运行中直接复制文件必定一致的保证。

仓库镜像设置 `DSH_HOME=/data/.dsh`，每人数据目录挂载到 `/data`，因此记忆位于每人数据根下的 `.dsh/crysound-memory/memory.sqlite`。已查阅的现有每日 restic 备份脚本包含整个 users 目录，只排除依赖与缓存目录，不排除此文件；现有首次备份日志也列出了 users。这个结论仅确认脚本覆盖规则，未确认线上当前脚本或归档中已有该文件。现有脚本直接读取运行中的文件，没有 SQLite 一致性快照步骤，因此备份一致性和本插件恢复仍待实测。

伙伴助理在测试账号验收一次：页面保存合成事实并记录条数、内容及版本 → 通过 SQLite backup API 取得一致副本，或在获准的隔离测试进程停止写入后让现有备份收录完整数据库 → 从该次备份恢复到另一个空的隔离个人数据目录（不覆盖正式目录） → 核对属主、目录 700 和文件 600，执行 `PRAGMA integrity_check` → 用同版本插件启动，确认页面能看到原记忆、条数和内容一致，且新会话召回相同事实。若用 SQLite backup API，须确认副本实际进入现有备份，并从归档恢复该副本，不能只恢复本地副本代替“备份 → 恢复”。验收记录应写明快照、恢复来源、实际 Node/插件版本和结果；本 PR 不修改正式备份任务，不把这项未验收说成通过。

## 后台自动学习（草稿，尚未发布）

这是 [#100](https://github.com/crysound/crysound-workpartner/issues/100) 的实现草稿。设置页显示“使用记忆”和“自动学习”（默认开），两项分别持久化。任一关闭时后台不枚举或读取会话、不调用辅助模型；关闭期间的消息不在再次开启后补读。主对话主动保存仍沿用“使用记忆”和既有工具规则。

调度通过宿主 `agent/status` 观察运行/空闲；每分钟复查持久会话中的新完成本人轮次，不调用计数模型。仅顶层会话且没有活跃运行时，空闲约 15 分钟后补记；北京时间凌晨 2 点之后每日补查一次。宿主不在线则启动后查每日状态和未处理轮次。零新本人轮次或只有排除内容时不调用模型。水位与记忆和历史同事务提交，失败、取消、版本冲突不推进；进程内防重和有期限的跨进程租约避免重复提交，单会话失败默认等待 15 分钟再试，不阻塞其他会话。

辅助请求默认 `magpie / deepseek/deepseek-flash`，有 60 秒超时、48KB 输入和 1200 输出令牌上限，每人每天最多 20 次（失败和重试也计入）。路由必须由部署环境提供；这里不创建凭据或绕过宿主接外部模型。可在插件配置修改 `learningProvider`、`learningModel`、`learningIdleMs`、`learningPollMs`、`learningRetryMs`、`learningTimeoutMs`、`learningDailyHour`、`learningTimeZone`、`learningDailyCalls`、`learningInputBytes` 和 `learningOutputTokens`。输入过长、路由不可用或超限会记宿主警告并保留水位，不声称保存成功。

取材限 `source.kind=user` 的本人纯文本，排除子会话、继承历史、工具/机器人来源、附件混合消息、引用、转发、文档/邮件正文、假设、一次性要求和已知拒存内容。“这次别记”等停记要求在整个会话的后续轮次持续生效。纠正后不使用更早的证据；长时间未处理时只取最近累计 6000 字的完整候选消息。歧义材料保守排除，所以可能漏记。宿主没有给无标记纯文本提供“手打/从文档粘贴”的来源标记；本实现不能辨认这两者，不能宣称绝对排除未标记粘贴材料，真实负例评估仍须核实。

模型返回最多三条新增，每条有本人消息编号、至少八字的连续原话及原因。校验器核对来源和原话，正文只能逐字采用原话，标题也须取自原话；不接受补全推测或夹带本轮任务。更新沿用原编号；删除须原话明确要求忘记对应标题；合并须明确提及每个标题，内容只能连接已有事实。八成用量后只整理不新增。该办法保守限制扩写，不把关键词检查当完整语义证明；主对话已有工具的提取和拒存规则未改。

学习记录显示“新记住 / 整理了 / 删除了 / 合并了”、原因及每处前后内容，同次提交共用运行编号。记录与事实同事务提交；逐条撤销核对完整后状态，不能覆盖后来编辑或超额。手动删除会清掉所有相关历史及辅助请求原文；清空同步清历史。后台删除本身属于可撤销操作，前值只在学习记录的 30 天窗口保留。启动、写入、历史读取和定时复查擦除过期原文，沿用 `secure_delete`，不保存含原文的墓碑或自动备份。

首次实际学习成功后，同一会话与回复轮次下显示“已记住”回执，并说明“我会自动记下你的长期偏好，可在设置里关闭”。页面使用一个共享轮询读取已提交事实的标题，不按每条回复重复请求；失败或待提交提案不生成回执。删除或撤销后不再从学习记录生成该回执。

管理接口沿用相同来源、方法、请求体大小与版本验证：`POST /crysound-memory/api/auto-learning` 接受 `{revision, autoLearning}`；`GET /crysound-memory/api/learning` 返回一致的事实与记录快照；`POST /crysound-memory/api/undo-learning` 接受 `{revision, id}`；`GET /crysound-memory/api/receipts` 只返回本人已提交且仍存在的事实标题和会话/轮次，不返回候选原话。普通召回不读取学习历史或辅助日志，召回预算不增加。设置提交成功而历史刷新失败时保留提交结果，显示未读完成，不能当成空历史。

隔离合成验证覆盖真实 SQLite、HTTP、宿主工具、调度/辅助流协议、重启水位、取消和版本冲突；其中辅助响应为测试替身，不能证明真实模型效果。[原页面准备证据](tests/evidence/learning-preparation/README.md)和[本轮复查](tests/evidence/learning-implementation/README.md)分别说明来源。[固定困难集与评分办法](../memory-evaluation/LEARNING-EVALUATION.md)先于真实调用提交，要求困难集提取至少提高 10 个百分点，原集不退化，负例误记和无依据扩写均不升。[本轮真实结果](../memory-evaluation/results/2026-11-07/README.md)：回归 18/18→18/18，困难集 41/41→41/41，增益零；困难负例 1/10→1/10，无依据断言 3→3。一段后台提案被拒绝，正式验收未完成。不能以基线满分代替提取提升，仍保留草稿。

## 存储格式与运行时升级

学习扩展的格式标记为 2，但 `PRAGMA user_version` 保持已发布的 1，`meta` 仍只有原三个字段，事实 `source` 仍为 `conversation/manual/edited`。0.1.2 不只检查格式号，还使用不列字段的 `INSERT OR IGNORE INTO meta VALUES (1,0,1)`，并逐条校验来源；因此不能给旧表直接加列，也不能引入旧版未知来源。新增 `learning_settings`、学习记录、水位、每日状态、请求日志、回执、调用额度、租约和失败重试表，与旧事实同库；所有扩展表均不进入旧版召回。已有事实、版本和原开关保留，初始化与校验同事务完成；未知格式拒绝加载，不清库。此前未发布草稿格式 2 的额外列和来源会在事务内转换回此兼容表示。

回退时直接使用已发布 0.1.2 包即可，不需要替换数据库。`tests/fixtures/store-0.1.2.mjs` 是提交 `18f0fcd1c8` 的实际发布代码，回退测试让它打开升级库、读取后台事实、写入和删除，再让新版重开。数据库触发器保证旧版删除/清空也清理学习历史和辅助日志，避免镜像回退后遗忘失效。恢复较早格式 1 快照后，新版可再次创建扩展表并保留原事实；恢复后学习开关采用该快照所含状态，没有该设置则默认开。原会话和外部备份仍不由本插件清除。

辅助请求在调用前把精确 system/messages/route/purpose 写进本人同库的私有日志，不送进主对话。日志与学习记录同样最多保留 30 天；手动遗忘/清空会同步擦除这些副本。日志不包含凭据，调用次数的纯计数不因删除原文而清零。


## 升级 dsh / 升级 Node 镜像时复查

- Node 内置 `node:sqlite` 仍是实验性接口；升级 dsh 或 Node 镜像时，重跑存储、HTTP 管理、真实页面删除及备份恢复检查，不增加兼容层。仓库 `crysound/web/Dockerfile` 固定的是 `node:24-bookworm-slim`（主版本 24，未锁补丁或摘要），已完成隔离实测的运行时为 Node **24.22.2** / dsh **0.2.2-rc.1**；每次重建可能取得不同 Node 补丁，伙伴助理应记录实际 `node --version` 后再验收。桌面版实际内置 Node 仍待目标平台确认。
