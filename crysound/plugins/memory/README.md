# 兆华记忆

`@crysound/memory` 是工作伙伴的独立记忆插件，不修改 dsh 本体，不加入预装。主对话模型从用户本轮陈述中主动保存稳定的偏好、身份和长期项目事实；不增加后台摘要模型调用，不下载嵌入模型，不接向量库或新外部服务。自动提取由主模型遵循工具说明完成，不保证每个事实都会被提取。

## 使用

通过宿主支持的插件入口安装固定版本的包后，设置中出现“兆华记忆”。同一人的新会话自动获取全部已保存事实；每条只保存一个概念，用户可以查看内容、确认删除指定记忆，也可以在对话里要求忘掉。页面删除和模型遗忘使用同一存储事务。第一版只有查看和删除；纠正事实可在对话中重新说明。

默认保存最多 50 条，每条标题最多 40 字、内容最多 240 字。召回 JSON（包含全部事实、编号和版本）的总量不超过 6000 个 JavaScript 字符；固定操作说明另计，字符不是 token。数量和召回预算可在 profile 中配置 `maxMemories`（1–200）、`recallChars`（512–24000）。达到任一上限就拒绝新增并提示整理，保留原有事实，不自动删旧内容。页面显示已用条数，条数满额时明确提示“记忆条数已满，请先删除不再需要的记忆，再记新内容”；未满时也说明内容上限及先删再记的处理方式。降低预算导致已有事实超额时加载明确失败，应先用原预算整理后再降低。

## 数据与安全

唯一长期记忆源为 `$DSH_HOME/crysound-memory/memory.sqlite`，未设置 DSH_HOME 时使用 `~/.dsh`；不会探测或写入其他项目、全局指令文件、每日工作日志。网页版由每人的持久化挂载区隔离，同一人不同工作区共用个人记忆。桌面版在本机 DSH home 独立保存，暂不跨端同步。Node 24 自带 SQLite，无额外运行时依赖或原生模块安装。数据库文件权限为 600，目录新建时为 700。

SQLite 事务串行处理并发写入，读写携带版本，冲突明确返回失败；旧版本的保存不能覆盖新事实或复活刚删除的事实。删除使用 `secure_delete`，不写含原文的墓碑、自动备份或删除日志，不另起后台任务从旧聊天重新提取。每轮重读当前记忆，记录在宿主系统提示词快照中。原会话中的历史工具输出、模型请求和既有备份仍保留原文；这不是聊天记录清除功能，旧会话中已出现的信息也不可能从模型已见的历史里撤回。

提示词要求不记凭据或一次性内容，写入边界还拒绝密码、令牌等中英文标签和常见密钥格式；无法识别完全没有标签、也不具备已知格式的任意秘密。存储仅供个人事实使用，不应当作密码管理器。记忆以 JSON 数据呈现且明确不是指令；仍不能保证主模型绝对不受恶意记忆影响。

管理接口沿用 `webStartup.trustedHosts` 及监听地址，校验 Host、Origin、Fetch Metadata、方法、请求体大小和版本。不新加授权域名，不绕开飞书身份网关；测试入口能打开不代表正式公司网关已验收。

## 备份与恢复验收

存储显式设置 `PRAGMA journal_mode=DELETE`，**不使用 WAL**。事务期间仍可能出现回滚日志；不能把“没有 WAL”当成运行中直接复制文件必定一致的保证。

仓库镜像设置 `DSH_HOME=/data/.dsh`，每人数据目录挂载到 `/data`，因此记忆位于每人数据根下的 `.dsh/crysound-memory/memory.sqlite`。已查阅的现有每日 restic 备份脚本包含整个 users 目录，只排除依赖与缓存目录，不排除此文件；现有首次备份日志也列出了 users。这个结论仅确认脚本覆盖规则，插件尚未装入正式备份，未确认线上当前脚本或归档中已有该文件。现有脚本直接读取运行中的文件，没有 SQLite 一致性快照步骤，因此备份一致性和本插件恢复仍待实测。

伙伴助理在测试账号验收一次：页面保存合成事实并记录条数、内容及版本 → 通过 SQLite backup API 取得一致副本，或在获准的隔离测试进程停止写入后让现有备份收录完整数据库 → 从该次备份恢复到另一个空的隔离个人数据目录（不覆盖正式目录） → 核对属主、目录 700 和文件 600，执行 `PRAGMA integrity_check` → 用同版本插件启动，确认页面能看到原记忆、条数和内容一致，且新会话召回相同事实。若用 SQLite backup API，须确认副本实际进入现有备份，并从归档恢复该副本，不能只恢复本地副本代替“备份 → 恢复”。验收记录应写明快照、恢复来源、实际 Node/插件版本和结果；本 PR 不修改正式备份任务，不把这项未验收说成通过。

## 升级 dsh / 升级 Node 镜像时复查

- Node 内置 `node:sqlite` 仍是实验性接口；升级 dsh 或 Node 镜像时，重跑存储、HTTP 管理、真实页面删除及备份恢复检查，不增加兼容层。仓库 `crysound/web/Dockerfile` 固定的是 `node:24-bookworm-slim`（主版本 24，未锁补丁或摘要），已完成隔离实测的运行时为 Node **24.22.2** / dsh **0.2.2-rc.1**；每次重建可能取得不同 Node 补丁，伙伴助理应记录实际 `node --version` 后再验收。桌面版实际内置 Node 仍待目标平台确认。

## 检查与交付

轻量检查：Node 24 执行 `node --check index.mjs`、`node --check store.mjs`、`node --check panel.mjs`、`node --check client.js` 和 `node --test tests/*.test.mjs`。测试覆盖持久化、删除后原文移除、旧版本拒写、预算与满额回滚、凭据拒存、独立用户目录和真实 HTTP 管理接口。仓库中的测试另从已提交的真实模型合成会话快照无密钥回放保存、召回、两种删除及重启，不调用模型；单独发布的运行包不包含测试及评估资料。

界面和存储结构已获分诊确认，沿用中文管理页和分条 SQLite。部署由伙伴助理打包并仅安装到隔离测试账号；不发布市场、不改预装或正式容器。按 [隔离实测步骤](../memory-evaluation/TRIAL.md) 验收自动保存、新会话召回、遗忘、重启复查、中文页面查看/删除、公司域名代理及上面的备份恢复。正式网关、桌面版、备份恢复、长期并发和提取率仍未验收，不阻挡交测试账号打包验收；验收后由伙伴助理征得负责人同意才预装。候选评估及真实证据见 [评估目录](../memory-evaluation/README.md)。
