# 隔离实测结论

北京时间 2026-11-07 补测，选择**自写最小实现 `@crysound/memory`（兆华记忆）**。fooxe 和 palace 的自动保存、跨会话召回可用，但原版遗忘路径不满足要求；修补它们还需移除自动清理或每日日志、收窄写入目录、重做中文管理与并发处理。保留最小的事实存储和三个工具，维护面更清楚。

## 候选实测

| 项目 | fooxe 0.13.10 | palace 1.8.4 |
| --- | --- | --- |
| 自动保存 | 环境负责人命令行记录通过；本轮网页重测无“记住”指令也调用 `memory_save`，真实面板出现记忆 | 本轮网页调用 `memory_note_user`，用户 MEMORY.md 保存沟通偏好，后台今日日志保存工作与咖啡偏好 |
| 新会话召回 | 环境负责人四轮记录确认新会话召回报告格式、咖啡与背景 | 新会话从插件投影中召回沟通、工作和咖啡；不是继承前一会话 |
| 对话遗忘 | 负责人记录中没有删除工具，模型尝试文件修改被权限阻止，后续新会话仍回答原咖啡偏好；判失败 | 经预览、文字确认及原生 Allow once 后工具报告成功，但后台日志又写回含原文的“已删除”说明 |
| 删除后复查 | 本轮从真实英文面板确认删除整条记忆，列表变空，新会话 `memory_search` / `memory_list` 后回答不知道；网页删除路径通过 | 新会话回复没有把咖啡当当前偏好，但 `user/message` 的 `plugin:dsh-memory-palace` 投影仍含“已删除：只喝无糖拿铁”原文；不满足删除后不再注入 |
| 管理页 | 能查看、删除；一条记忆可混合多个偏好，整条删除会一起移除；面板主体英文 | 存在中文配置页，但完整逐条记忆管理本轮未验收；headless 依赖 Web 服务，不能激活 |

关键 palace 证据：`session-61b39647-602f-4c4c-989c-80dd480d3185` 的 seq 10，是删除后独立会话的插件投影，含被删事实原文；原会话的历史记录保留不是此次失败判据。fooxe 网页面板补测的保存会话是 `session-affe6f92-9d0b-42ff-8567-8d9dbdfec2e3`，面板删除后的会话是 `session-7df9846e-0b71-45c9-b11e-7f287799c554`。这些均为合成测试人物与偏好。

官方插件不从旧聊天重新抽取，也不保存“已删除某事”的文字；原聊天记录和既有备份仍保留，不能把长期记忆删除描述成聊天记录清除。模型自动提取及不保存一次性内容仍依赖提示词，密码标签与常见凭据格式另有写入拦截，不能承诺识别任意未标记秘密。

## 环境、资源和证据边界

- dsh 0.2.2-rc.1、Node v24.22.2；已有一次性测试容器和现有模型接入，没有新钥匙、向量库、嵌入模型、镜像构建或新外部服务。真实回复的 provider/model 为 magpie / codex/gpt-6.1-sol，测试轮廓沿用环境提供的 Low 推理等级。
- fooxe 命令行结果来自环境负责人交回的四轮记录，本轮补了真实网页保存和面板删除。palace 与官方插件的网页三轮/多轮记录由本轮核对。Web 测试各 profile 只装载一个记忆候选，但共享测试 HOME/工作区及会话列表，并非严格分 HOME 的对照实验；各插件的记忆目录不同，全部合成测试，无正式用户数据。正式演示应使用独立测试 HOME 和工作区。
- `trial-evidence.json` 只导出指定合成会话的主模型 provider/model、原始 usage、记忆工具及召回快照。palace 的三段记录分别有 3 / 6 / 2 次主对话模型调用；官方首次保存 5 次主调用，后续纯召回各 1 次。调用数包含工具往返，不包含标题生成和 palace 后台整理；样本提示词、工具及缓存不同，不能据此算提速或费用比例。未取得后台调用账单与成本，不编造金额。
- 321 / 228 / 117 是事实 JSON 的 Unicode 字符数，本组没有非 BMP 字符，因此也等于 JavaScript UTF-16 长度；固定操作说明不计入这些数值，字符不是 token。配置的 6000 字符是全部事实 JSON 的上限，主模型工具往返仍增加上下文与费用。
- 新目录为个人 DSH home 下 `crysound-memory/memory.sqlite`；SQLite 是 Node 内置的实验性 API，后续 Node 升级需复测。实际数据结构、事务、预算和边界说明见 [插件 README](../memory/README.md)。

**仍未验收：**正式公司域名经网关查看/删除、桌面版加载/管理、现有备份覆盖与一致性恢复、大规模/长期并发及模型提取率。候选的所有写入目录和后台网络行为未做完整系统跟踪；不可将功能样本当作全面隔离或安全审计。PR 的中文界面和新持久化结构先交分诊确认，不直接交付上线或预装。

## 分诊答复后的补充核对（2026-11-07）

按已确认方案保留中文设置页和本人持久化目录内的分条 SQLite。数据库显式使用 DELETE 日志而非 WAL；镜像源固定 Node 24 主版本、没有锁补丁，隔离运行时实际为 Node 24.22.2。升级复查与现有备份覆盖规则、一致性限制和恢复验收步骤已补入[插件 README](../memory/README.md)。未执行正式备份或恢复，不以脚本覆盖规则代替归档恢复证据。

本轮补充已用条数及先删再记提示；管理接口返回配置上限，模型召回格式和预算不变。9 项 Node 24.14.0 轻量行为检查通过，包含真实 HTTP 响应中的上限及删除后结果。测试服务器改为逐条显式匹配路径，替换远端代码扫描标记的动态处理函数查找；告警是否清除须以新提交远端扫描为准。

真实页面复查使用规则配置的持久浏览器独立标签页，宿主仍为一次性测试容器内 dsh 0.2.2-rc.1 / Node 24.22.2；使用本轮全新 DSH_HOME、DSH_AGENTS_HOME、工作区及端口，直接加载本轮插件源码，无安装、构建、模型调用或正式数据改动。为检查满额状态，脚本通过存储 API **预置 50 条合成事实**（不是自动提取测试），默认预算下事实 JSON 为 4505 个 JavaScript 字符。实际设置页显示 50 行和“已保存 50 / 50 条记忆。记忆条数已满，请先删除不再需要的记忆，再记新内容。”点击删除并确认后显示 49 行和“已保存 49 / 50 条记忆。达到条数或内容上限后，请先删除不再需要的记忆，再记新内容。”无页面错误，满额提示随真实删除结果消失。

本轮没有重跑已完成的模型提取场景。正式公司网关、桌面版、备份恢复、长期并发和提取率仍未验收，交伙伴助理在测试账号继续验收；验收后须再获负责人同意才预装。
