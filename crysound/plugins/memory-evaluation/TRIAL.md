# 两款候选的隔离实测

这是待执行的验收步骤，**没有任何候选已通过的含义**。本地开发助理不装依赖、不建镜像；由中台提供一次性环境或明确的测试 profile 入口后，接着执行本页，不重做已完成的源码初评。

## 环境与证据

用 dsh 0.2.2-rc.1，Node 至少 24.9，默认模型 GPT-6.1 Sol 经现有 magpie 接入；不得自行换模型、增加密钥或服务，不把钥匙写进命令、需求单或日志。记录真实返回的模型名及可获取的调用用量，不仅记录设置里的名字。若模型或工具不可用，记阻塞，不能把环境失败算成记忆失败。

两款使用互不共享的测试 HOME、DSH_HOME、工作区和 profile，也不挂载本人正式数据。若只能提供测试 profile，要额外隔离 HOME/工作区；仅换 profile 名隔离不了这些插件的全局记忆。测试前保留各自目录快照、初始空记忆状态及其他插件清单；不预先写记忆，不手工调用保存工具帮它通过，不从正式用户目录复制配置/凭据。沿用中台给出的现有模型接入。

环境负责人用宿主支持的安装入口安装以下固定包；`<profile>` 换成专用测试 profile，安装前检查包与 `candidates.json` 一致：

```sh
dsh plugin --profile <profile> add @fooxe/dsh-memory@0.13.10
# 另一个隔离环境中执行：
dsh plugin --profile <profile> add dsh-memory-palace@1.8.4
```

不要在一个环境装两款。保留安装输出、加载警告、版本兼容检查结果，不擅自加豁免。其余会话创建与运行使用该环境已经验证的网页/CLI 入口，不能虚构 SDK 或 CLI 参数。若网页步骤需交给浏览器执行，只交网页步骤；业务判断及回执仍由本轮负责人处理。用当轮实际浏览器或 partner-issue 配置的持久浏览器入口，在同一会话开独立标签页，不借用桌面应用未传入的连接。遇到只有本人能恢复的登录，按中台待处理约定结束。

保存每个真实会话的标识、开始时间、用户原文、助手回复、工具调用/结果及脱敏日志。截图或导出中不得包含真实凭据、其他人的聊天。另存最终记忆文件及前后目录差异；本页的步骤不能代替实际证据。

## 每款独立执行同一组对话

| 步骤 | 输入/操作 | 通过证据与失败判定 |
| --- | --- | --- |
| A 自动保存 | 全新会话输入：「我平时做声学测试方案，工作沟通习惯用简体中文；我喜欢先给结论，再给三条理由。请用这个风格介绍一下工作伙伴能怎么帮助我。」不要说“记住”。 | 等本轮和插件后台任务完成；从真实工具日志及最终记忆文件确认是否自动保存上述稳定偏好。只在回复里复述偏好、只存在当前聊天上下文都不算。区分长期记忆和每日日志。 |
| B 新会话召回 | 关闭/离开 A，新建独立会话 B，同一用户同一测试工作区；输入：「帮我写一份测试方案的开场说明，按我平常的沟通习惯来。」不提 A 的内容。 | B 不继承 A 会话历史；从真实模型请求/持久会话证据核对记忆进入了上下文，并观察是否采用简体中文、结论先行、三条理由。不仅凭“它碰巧这样回复”判断召回。没有保存与保存了但未召回分开记录。 |
| C 遗忘 | 在 B 输入：「以后不要记住我喜欢三条理由这件事，请忘掉这一条；简体中文和结论先行可以保留。」允许插件正常人工确认流程。 | 核对调用的是哪条删除/编辑路径、文件里该条是否真的移除或仅标删、其他偏好是否保留；记录无专用遗忘工具时助手实际如何处理。不要替助手手改文件使它通过。 |
| D 删除后召回 | 等待后台任务完成，创建独立会话 C；输入：「你还记得我对回答形式有哪些固定偏好吗？」再重启测试 profile 后新开会话复查。 | 检查实际记忆注入/检索输出是否仍含三条理由，不能只信助手说“忘了”。扫描插件的日志、索引、备份/墓碑，区分“停止召回”和“插件数据中已移除”。若后台整理又从旧会话把被删事实写回来，判为未通过遗忘。原聊天历史本身保留不等于仍被长期记忆召回。 |

默认能力测完后，在隔离环境追加这些检查，结果另列，不混入上述结果：

- 用明显声明为测试内容的假密码和假令牌探测拒存，不能使用真实凭据。确认是否只在提示词承诺不记，还是写入边界也拒存；项目一次性进度不应成为长期偏好。
- 设置页查看一条记忆、删除指定测试条目，再创建会话核对；记录界面是否中文，管理页是改配置还是可管理实际记忆。通过真实网关的测试入口验证来源检查；直接 localhost 成功不等于公司域名成功。
- 在两个会话分别保存互不相同的测试偏好，确认没有丢写入；不同用户的独立测试挂载中不可见对方数据。只用测试数据，不改正式用户名单或容器。
- 记录写过的全部目录、后台进程与网络目标。区分现有对话模型调用和额外摘要调用；确认没有启动/下载嵌入模型、向量服务或调用新外部服务。不要打印包含凭据的网络请求头。
- 记录每次实际注入的字符数、可用 token 计数及模型调用次数。字符数不是 token 数，没有账单数据就不编造费用。查看备份是否覆盖新目录由伙伴助理负责；本页不触发正式数据恢复。

## 结果填写

在需求单同一评估评论下补充，保留本次初评的未验收声明直至有证据替换。每款独立填写：

| 字段 | 内容 |
| --- | --- |
| 版本/环境 | 插件精确版本与完整性、dsh 与 Node 版本、其他插件、真实模型及接入、测试 profile 隔离方式 |
| A / B / C / D | 每项通过/失败/阻塞；会话与文件证据位置；界面文字或助手自述不能单独作证 |
| 界面 | 查看/删除是否可用、是否中文、经域名入口是否可用 |

| 资源/费用 | 实际调用次数、额外后台调用、可得的 token 用量；没有实测则填未测 |
| 结论 | 复刻哪款或最小实现及理由；与源码初评的差异；仍未通过的验收项 |
