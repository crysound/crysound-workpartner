# 三方向：三种设计，不是三种皮

改编自 huashu-design 的 directions 流程。共享 spec 和真实品牌资产；不能为了彼此不同牺牲内容。六候选只是探索，交付三份可见初稿。

## 六张方向卡

最佳设计师思路出两张，同媒介现实参照出两张，本地样张库出两张。每卡记录一句定位、版式骨架、视觉主角、字体角色、内容密度、与其他候选的差别和参照是否亲眼见过。品牌已定时全部使用同一套公司色和标志。

本地样张分 web / app / info / east，先看总览再看单张。轮盘可以用当前秒数对该分区张数取余选图，迫使自己探索通常不会选的结构；不把随机色板覆盖品牌。只看图片，不加载外部样张网页。

## 三份真实初稿

选彼此最不同的三个骨架，每方向一份完整 HTML：网页有首屏与完整滚动内容，App 有主要路径和详情，海报有最终尺寸下能读的核心信息。六格缩略图、三个完整版本和各自截图放在项目目录。依次用 `scripts/render.mjs` 渲染，比较页只引用产物相对路径。

对比时遮住颜色看结构是否仍不同：视觉起点、图文比例、内容次序、密度、用户路径至少有实质区别。若只换皮，用其他候选替换。截图要亲眼看过；没渲染不能说已验证。

## 选择与迭代

展示三个方向的具体长处和代价，结束回合等待选择。选定原话存 `direction-approved.md`，之后仅迭代选中方向。用户本次明确跳过或原项目已选方向时写明依据；机械截图、修错字不重新走方向门。
