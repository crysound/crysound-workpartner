# App 交互原型

先定义主要任务和最短用户路径，再设计首页、详情、关键动作、空白与错误状态。不要把多屏原型排成一行没有主次的手机。展示板让一张主屏讲清核心任务，其余屏解释流程关系；每屏的字要在目标手机尺寸读得清楚。

可参考 `assets/ios_frame.jsx` 和 `assets/android_frame.jsx` 的设备外壳，不手画失真的系统状态栏。设备外壳不必进入真实业务界面。仅使用本地 HTML/CSS/JS 即可实现，不要求 React 或 Babel。公司品牌优先 DESIGN.md，样张只借结构。

三个方向各做可操作的最短路径，用真实截图比较。选定后至少点通进入详情、关键动作和 tab 切换，控制台无错误；用 375×812 验收并核查 44×44px 点击区、键盘焦点、滚动和返回行为。点击测试使用同一共用运行时的 `withBrowser` 包装，不另起浏览器下载流程。
