# #120 公司工具效率提示的隔离实测

本批三轮达到需求的合成题目标：读文件中位数低于 20 秒且输出 token 减少；脚本少两次主对话请求；18 次答案全部正确。耗时仅代表这批合成题的趋势，网页、桌面与完整插件组合的上线验收仍待完成。

## 条件与判定

2026-11-07（北京时间），Linux 8 核共享测试机、现有 dsh 0.2.2-rc.1 发布运行时、Node 24.22.2。每种配置、每类题各 3 次，顺序为每题 before→after，逐轮交错；每次创建新会话和新工作目录。开始时负载为 3.32/3.37/2.95；其他隔离测试仍在同机运行，没有停止它们。

两侧均为 GPT-6.1 Sol（`codex/gpt-6.1-sol`）、medium、headless、权限策略 never。基础公司补丁同为 a28f728d，两份补丁的 SHA-256 均为 `e8f0b9bd1e33d2a4097ab1d341b3b9a19204bfd36ed29ffa7cd0a9480a985598`。after 仅插入实际升级器生成的公司提示模块；模块 SHA-256 为 `6570e8a9324e4b9ccf5779a917bc711c2cbb06d0bef6760633a92bc31876f4ea`。检查了各会话系统消息：after 全部含公司例外提示，before 全部不含；18 次请求头中的原生工具定义哈希相同。固定模型与推理配置最后叠加，实际服务的模型也逐次核对。

题目来自固定种子的合成数据，与仓库离线示例生成器的题目不同。qa 要求一句话解释 HTTP 404；read20 在 20 个源文件中找出真正定义的常量，排除注释旧值与同前缀常量，正确答案为 14 个文件、总和 25150；script 在 80 行 CSV 中只汇总 status=ok 的金额，按地区合计降序输出。每个脚本均由入口独立重跑，逐行核对输出，并核对答复包含所有结果。两侧共 18 次完成、退出成功、正确，模型网关非成功响应为 0，工具错误为 0。

会话计时为会话 turn/start 到 turn/end；命令计时还包含启动与退出，不含入口独立重跑脚本的正确性检查。两种计时都达到读文件中位数小于 20 秒。输出 token 按供应商通过会话记录报告的值，未单独估算隐藏推理；输入用量区分未缓存与 cacheReadTokens，不能把 runs.csv 的 inputTokens 当作完整输入上下文。

每次网关请求数比主对话请求多 1，额外请求来自标题生成：qa 两侧为 2；read20 从 5 变为 4；script 从 6 变为 4。权限策略为 never，未测自动审查模型的额外请求。

## 延迟依据和限制

会话自身的逐步时间戳显示：读文件改前模型阶段（step/start 至 assistant/message，含提示准备、服务等待和生成）合计中位数 22.227 秒，改后 15.230 秒；所有工具执行耗时之和分别只有 0.403–0.571 秒和 0.120–0.174 秒。改后每次两个调用都按先后执行，无并发计时重复；改前求和含并行工具的重叠，因此是本地工具耗时的上界。耗时主要留在模型阶段，继续优化文件执行本身不能再带来同量级收益。脚本对应模型阶段为 16.196→13.848 秒，工具耗时为 0.217–0.243→0.115–0.149 秒。

基线读文件的范围宽于两侧中位数差，且两侧均有前缀缓存命中；这里仅报告本批观察，不将耗时比例当作稳定的生产性能提升。三次不提供显著性结论，也不代表任意模型或大项目。头尾顺序固定，交错只能减轻时间漂移，不能消除缓存、共享负载与模型随机性。调用数量减少和所有答案正确有逐次记录支持。

原生提示原本要求只能用单文件读取/搜索工具。公司提示明确将同一执行环境内的批量检查列为例外，保留权限、专用读取器和跨执行环境的限制；因此采用已有 shell 即可，不增加批量工具、服务或依赖。独立调用同轮并行的提示仍保留。
