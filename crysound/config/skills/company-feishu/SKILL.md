# 飞书与飞书项目

本技能优先于官方技能中的应用配置和登录说明。只用本人身份，不创建应用，不索取应用密钥，不使用机器人身份。

先执行 `lark-cli auth status`（飞书）或 `meegle auth status`（飞书项目）。未授权时把包装器返回的授权链接原样交给本人，等本人完成后再继续。不要反复请求本人尚未授予的权限，不把失败或空结果说成成功。

飞书授权统一在工作伙伴的设置 → 飞书授权中管理。不要执行官方 `lark-cli config init`、`auth login` 或切换到 `--as bot`。包装器每次从网关领短期令牌，长期凭证留在网关；不要读取、打印或复制任何令牌文件。

飞书项目独立授权，执行 `meegle auth login --device-code --phase init`，把返回的 `verification_uri_complete`（否则 `verification_uri`）及 `user_code` 原样交给本人，再按官方技能用 poll 阶段完成登录。也可请本人在设置 → 飞书授权连接。网页版和云端模式共用云端授权；本机运行模式在桌面版单独连接。

命令缺失时把包装器给出的固定版本安装命令交给本人。不要自动升级 CLI、安装最新版或替本人登录其他账号。桌面版若当前会话找不到包装器，需重启工作伙伴，让新 PATH 生效。

按任务加载官方技能：文档 lark-doc，电子表格 lark-sheets，多维表格 lark-base，日程 lark-calendar，消息 lark-im，邮件 lark-mail，审批 lark-approval，任务 lark-task，知识库 lark-wiki，云盘 lark-drive，通讯录 lark-contact，会议 lark-meeting，项目 meegle。先读用法，再执行命令。官方 references 随同一固定版本提供。

发消息、发邮件、提交审批、删除、修改分享权限等写操作前，先完整展示对象、接收人、内容、附件、修改值及影响，得到本人对本次操作的明确确认后才执行。已有确认只适用于当时展示的内容，修改后重新确认。优先用 `--dry-run` 预览。

飞书 CLI 的退出码 10 表示高风险确认门禁。先把具体操作给本人看，取得确认后才在原始 argv 末尾追加提示中的 `--yes`。不要静默加 `--yes`，不要通过原生 API 或别的身份绕过确认。飞书项目的写操作遵循同样的确认规则。
