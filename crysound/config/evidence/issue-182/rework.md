# 抓取返工：拒绝空壳，读取公开文章，缩短微信失败等待

## 行为与依据

DeepSeek 原样返回 `We're sorry but 中国新闻网 doesn't work properly without JavaScript enabled. Please enable it to continue. 43.1万` 时，旧网关适配只检查 80 字符门槛，会将其当作正文。本轮对照同一响应，原主线接受、新适配拒绝；两路竞争测试确认另一条可读请求继续，空壳不能取消它。规则同样覆盖直抓、验证/登录提示、纯 Markdown 导航和计数；有独立长正文、在文中引用提示的文章仍可读。规则不做通用标题语义判断。

原中新网页 `https://m.chinanews.com/wap/detail/chs/zw/10714120.shtml` 在本轮持久浏览器中实际加载了标题“苹果公司发布搭载人工智能语音助手的家居新品”和完整正文；页面自身请求 `https://dw.chinanews.com/cns/app/v1/wapDetail/content/10714120.json?language=chs`。新适配只匹配该站点固定手机文章路径，沿用受检查的匿名公开传输读取同一 JSON，核对数值成功码 0、文章编号及字符串正文，原文章 URL 作为来源。HTTP 错误、截断、编号或结构不符仍进入既有兜底。普通网页抓取不变。

本机通过固定发布版抓取类和公司 `fetchPage` 实际读到 824 字符正文，含 HomeView、299 美元与 11 月 13 日发售；无 Chromium、无付费兜底、无摘要模型。首次测试发现真实成功码为数值，已据实修正夹具；另一次 1.5 秒直抓预算不足，因此已知公开文章接口使用可配置的 `fetchPublicArticleTimeoutMs: 3500`，普通页面仍是 1500 毫秒。修正后两次本机成功样本分别为 957 和 1443 毫秒，其中第一份保存在[实测结果](rework-public-result.json)。样本来自本机公网读取，不是用户容器端到端验收，不宣称整体提速或线上 7/8 已通过。

## 微信仍未救回

原文章为 `http://mp.weixin.qq.com/s?__biz=MzIxNzE3ODE3MQ==&mid=2651098970&idx=3&sn=f8b48572f7167952d0e6407abf117717`。本轮同一浏览器入口分别打开 HTTP 和 HTTPS，均跳至 `/mp/wappoc_appmsgcaptcha`，显示“环境异常 当前环境异常，完成验证后即可继续访问。去验证”。未解验证码，不把此提示算作正文。HTTP 现在只在 `mp.weixin.qq.com` 无身份信息、无非标准端口时规范成 HTTPS，完整保留查询参数和原始引用；这不保证克服站点验证。

伙伴助理最初交回：Treg 两次 8 秒超时，DeepSeek 一次 8 秒超时、一次 0.37 秒报错。网关未保留该次上游状态或错误，所以无法复原那次 0.37 秒失败的确切原因。本轮通过缺资料入口取得[新的单次 HTTP/HTTPS 对照](rework-wechat-result.json)：DeepSeek HTTP 在 1.19 秒返回状态 200、65 字微信验证页；HTTPS 为 8 秒读超时（实际 8.81 秒）。同一 Crawl4AI 提供方的 HTTP 回答 `ok=false, reason=cooldown, cache=archive`、无正文，服务内部报告 784 毫秒、命令总计 4.93 秒；HTTPS 在 8.01 秒由命令超时结束。两种协议都未获得正文，不能断言协议是唯一原因，也不将超时当成服务端明确报错。该对照由伙伴助理沿用既有授权完成四次调用，本开发进程未读取付费钥匙或自行派发付费请求。Crawl4AI 对照使用底层同一提供方，完整 `treg.web.extract` 和新代码仍需在用户容器验收。目录说明确认 `treg.web.extract` 正文只接受 `url`，不能直接加 `format` 或浏览器等待参数；底层 Crawl4AI 的其他选项包含增加费用的代理，未更改它们，也未改为直调其他端点。目录记载需真实浏览器的页面可能需要 10–30 秒，不据此宣称能在本单预算内救回微信。

微信直抓、两路兜底和摘要改用较短的共享 `fetchWechatTimeoutMs: 3500`，且不超过全局总预算。计时器回归证明：直抓耗尽 1500 毫秒后，两路只剩 2000 毫秒，届时同时取消并保留抓取失败；若两路更早失败则立即返回。不再让已知失败的微信调用耗满 9.5 秒，不增加重试、供应商或费用上限。3.5 秒是对已知失败页面的预算取舍，不是真实提供方性能测量；可能放弃更晚才能到达的正文，可通过配置调整。

## 本轮检查

流水线 14 项全部通过；固定发布工具 31 项通过、百度公网探测 1 项未启用，包含实际 Chromium、补丁重复执行/漂移拒绝、公开文章响应校验、工具参数和时限注册、两路取消与真实 Markdown 输出。完整工具检查的真实 Session 导入项因本机所选固定版临时依赖缺 `dsh-credentials` 未通过，未装依赖；之后明确排除该项运行其余检查，没有把它算通过。本轮未修改会话存储代码；这项仍需完整运行时核对。配置刷新在新建和已有的临时 profile 上执行，两个新时限均刷新，个人选项保留，第二遍字节一致。没有安装依赖、全仓构建或全套测试。

## 部署与验收

本次基于已上线 PR #184，只需重建网页镜像，同步 `partner.patch.yml` 和 `profile-upgrades.mjs`，先升级测试账号。不需修改网关、凭据、付费路由或权限。回退恢复原镜像和配置；仅调两个时限时同步配置并按既有策略重启。

新镜像由伙伴助理复跑原八页，目标至少 7/8 真实可读正文，特别核对中新网页原链接、标题和价格。此前六页成功是助理提供的旧版结果，本轮未复跑，不可与本机单页结果合计为已验收的 7/8。微信仍列失败，若能读到正文必须保留片段再计成功。核对失败时的较短预算、两路取消、账本与计时派发、普通直抓无付费；四个长尾页、三题性能目标和完整运行时 Session 检查继续按主说明验收。`docker exec` 的 headless 进程须手工设置三个入口环境变量，详见[工具说明](../../../web/web-tools/README.md#独立进程验收的环境)。
