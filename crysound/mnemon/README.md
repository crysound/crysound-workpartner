# Bundled Mnemon CLI

`releases.json` pins the shared CLI version and SHA-512 digests of the npm `@mnemon-dev/mnemon` native platform archives. The web image and desktop package preparation run `prepare.mjs` to verify and extract the executable, package metadata, README and Apache-2.0 license. The native executable needs no Node/npm launcher. Desktop resources contain it outside ASAR at `crysound/mnemon/bin`; the company Host environment prepends this directory to PATH.

To upgrade, choose one Mnemon release, update `version` and every platform digest from `https://registry.npmjs.org/@mnemon-dev/mnemon/<version>-<platform>-<arch>`, then rebuild both the web image and desktop installers. Do not update executables in place. Keep enabled plugins and Provider settings unchanged.

```sh
node crysound/mnemon/prepare.mjs /tmp/mnemon-build
node crysound/mnemon/smoke.mjs /tmp/mnemon-build/bin
node --test crysound/mnemon/prepare.test.mjs
```

Preparation also accepts explicit target arguments, for example `darwin arm64` or `win32 x64`. Only run the smoke on its matching OS/architecture. The image build and native desktop `afterPack` hook run the smoke against the copied payload: it launches `mnemon` through PATH with no Node/npm on that PATH, checks the version, writes a fact in an isolated temporary store and recalls it in a separate process. It never opens personal memory stores. Run preparation a second time to check repeatability when upgrading.

This CLI smoke does not validate dsh-mnemon's UI or agent integration. After deployment, install dsh-mnemon in a test account, confirm Mnemon Native is available on the memory status page, store a fact in a Memory Space, and recall it from a new conversation. Attach status and recall screenshots to the PR; repeat on the next Mac and Windows installers. No third-party remote Provider needs to be enabled.

## Web memory defaults

The Web startup command `profile-upgrades.mjs --web-preview` writes a top-level `id: mnemon` override with `remoteAccess: trusted-host`. Each Web Host belongs to one person behind the authenticated gateway; the plugin still checks the Host connection's management access. No bundle `insert` block is copied. Desktop startup does not pass this flag, so its local access and personal settings stay unchanged.

Before launching the Web Host, the same command initializes an empty default global root with the bundled CLI's public `mnemon --data-dir <root> store create personal`. The published Memory Spaces Source discovers Native databases on disk and activates the first discovered store; its page shows this personal space as `personal`. There is no published default-space configuration in 0.5.42. The initializer reads the Source's public storage inventory contracts and never writes its registry. Existing Native or remote spaces, inactive spaces, incomplete store directories, disabled memory and personal storage/provider overrides are retained. A profile marker records an existing or successfully created space, so later user deletion does not recreate it. Creation failure emits a warning, leaves no completion marker and retries at the next actual startup; it does not stop the Host or claim that memory is ready. Custom or dynamic storage is left to the plugin and the person's choices.

Sources: [published Source storage layout](https://www.npmjs.com/package/dsh-mnemon-source-memory-spaces/v/0.5.25), [Native Provider CLI requirement](https://www.npmjs.com/package/dsh-mnemon-provider-mnemon-native/v/0.5.10), and [Mnemon store commands](https://github.com/mnemon-dev/mnemon). The behavior check uses these exact published packages with the bundled 0.2.13 native CLI and the plugin's public composition/management testing API: the real Source discovers one active Native space, writes a fixture fact and a separate Source instance recalls it. This is persistence evidence, not a model conversation or Feishu acceptance.

Run `node --test crysound/tests/mnemon-web-defaults.test.mjs` in the existing pinned DSH runtime. For the Native integration cases, set `MNEMON_TEST_MODULES` to a fixture `node_modules` containing published `dsh-mnemon@0.5.42`, `dsh-mnemon-source-memory-spaces@0.5.25`, `dsh-mnemon-provider-mnemon-native@0.5.10`, and `dsh-mnemon-strategy-default-three-tier@0.5.12`, sharing the runtime's existing dependencies; set `MNEMON_TEST_CLI` to the bundled native executable. Without these variables, only the Web/desktop configuration checks run and the integration cases are explicitly skipped. All native writes use disposable test roots, and the recall check also executes the real Layered strategy's offered View route without a model request.

Keep `idleReview.agentTeams: pause`. The alternative `scoped` isolates tools but runs a maintenance model, can write runtime memory and documents, and defaults to up to 20 reviews per session with a 4096-token response limit and a five-minute minimum interval. Those are plugin limits, not a monetary cap or a guarantee against incorrect writes. Enabling it for everyone would add model usage and automatic writes, so this change leaves the existing policy and personal choices intact. Other optional enhancements remain disabled by the bundle defaults.
