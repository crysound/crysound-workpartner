# 工作区本地服务预览

网页版把 `http://127.0.0.1:<端口>/…` 和 `http://localhost:<端口>/…` 交给原生右侧栏 Browser，并保留右键、修饰键和工具栏的新标签页入口。编辑器继续只监听容器 loopback。客户端适配器只注入网页版；桌面本机模式保持直接访问 loopback。

## 部署前置条件

在 `web/.env` 设置 `PREVIEW_HOST`，例如 `preview.example.com`，主站为 `app.example.com`。预览域名不能和主站相同，也不能是主站的父域。建议使用同一站点下的兄弟域名，避免 iframe 第三方 Cookie 限制。每人每端口有独立的 `<端口>-<不透明身份>.PREVIEW_HOST`，多端口可以同时打开，Cookie、编辑器脚本和 Service Worker 不共享来源。

伙伴助理须为 `*.PREVIEW_HOST` 配置 DNS、HTTPS 证书及隧道路由，指向主站的同一个网关入口；必须保留请求原始 Host，不能把预览 Host 改成主站。根预览域本身不提供应用。只给根域名配置证书不够；多层子域名可能需要额外的通配符证书，须先核对现有证书范围及费用，涉及付费另行确认。

部署顺序：先完成分诊审查；同步服务器配置中的 `plugin-patches.mjs`；设置域名并重建网关；构建工作区镜像并先重建测试账号容器；验收通过后按现有空闲升级流程推进。没有 `PREVIEW_HOST` 时网关不启用预览，新镜像也能继续用原有入口启动。启用后网关为已开通用户写入专属转发凭证；自助开通和手工开通/升级使用同一派生算法。凭证位于现有用户数据卷，权限 600；不通过网页、模型输出或日志下发。无需单独创建或轮换网关主密钥。

网关需要重建（增加了 `preview/` 只读挂载和环境参数），镜像也需要重建（内置 Browser 补丁、转发进程和启动监督）。只重建网关无法让旧镜像访问 loopback 服务。内部转发端口 3092 不发布到宿主机、不配置公网隧道。

## 登录与隔离

`/_zp/preview/open?port=4710&path=%2Fslides%2Fdemo%2F` 是主站入口。客户端也可直接进入本人端口的 `/_zp_preview/start?path=…`。预览域先设 60 秒的随机 HttpOnly nonce，再回主站核对飞书登录及预览所有者，最后兑换绑定 nonce、本人、端口和主机名的一次性签名票据。拿到他人的预览地址会在主站被拒绝；拿到兑换链接的另一浏览器缺少 nonce，也无法兑换。兑换后立即清理 nonce 并跳回根路径下的原编辑器地址，路径、查询和 fragment 保留。

预览登录使用 `__Host-` Cookie（Secure、HttpOnly、SameSite=Strict、无 Domain）。凭证有效 10 分钟，每次 HTTP 响应续期，上限为原主站会话的到期时间。空闲过期后重新导航会经过主站核对；后台请求和过期 WebSocket 握手返回拒绝，不把登录页冒充编辑器响应。WebSocket 建立后保持至连接断开，重新连接时再次鉴权。网关重启丢弃已使用票据记录；已清理的浏览器 nonce 仍不再可兑换。

只能转发 1024–65535 中的端口，拒绝 3080、3090、3091 和转发器自身的 3092。转发器固定目标为容器的 `127.0.0.1`，同时校验专属凭证和网关 DNS 当前解析出的来源地址，不接受外部目标主机。不会把编辑器改为监听 `0.0.0.0`。

HTTP、保存请求、SSE 和 WebSocket 流式经过网关与转发器。浏览器伪造的转发头和内部凭证会被移除；主站 Cookie 和预览登录 Cookie 不进入编辑器。编辑器自己的 Cookie 保留，但响应中的 Domain 被移除且不得覆盖预览认证 Cookie。同端口 loopback 重定向改为对应预览来源。不同来源的写请求和 WebSocket 被拒绝；主站也拒绝由预览页面 Origin 发起的请求。网关只接受配置过的主站、旧站、预览主机及内部服务主机，预览 Host 不能落回主站接口。

## 客户端与插件补丁

镜像构建时对已发布的 `@deepseek-ai/dsh-client-ui-sidebar-browser` 的 `lib/client.js` 打公司补丁，不改上游源码。补丁通过同步 DOM 事件调用公司 URL 适配器；没有适配器时保留原链接。聊天点击交给原生 Browser 注册，不另造侧栏。地址栏和保存的预览地址使用同一套 Browser 流程。

`plugin-patches.mjs` 只改 `dsh-claude-artifacts/lib/client.js` 的 URL 和 `src`，并支持 pnpm 的间接依赖布局；不复制或改动其 skills、editor 或授权声明。补丁重复执行不再改文件；上游升级未命中时打印现有告警。镜像内置 Browser 补丁在构建阶段以 root 执行，避免普通用户在启动时修改全局安装目录。

当前桌面壳只启动本机 Host（见 `apps/desktop/src/main.ts` 的 `DesktopHostProcess`），尚没有连接云端工作区的模式切换入口。本改动不新增该产品入口；在壳内加载云端网页版时使用云端适配器。未来若在 `dsh-app:` 文档中接远程 Host，须按工作区来源注入此适配器，不能全局改写本机链接。原生桌面云端模式须随该模式实现另行验收。

## 本地检查

无需装依赖、构建或连接线上容器：

```sh
node --test crysound/web/preview/tests/preview.test.mjs
node crysound/web/preview/verify-patches.mjs /tmp/browser-package /tmp/artifacts-package [/tmp/another-artifacts-package]
```

第二条的输入是官方 npm 包解压后的 `package/` 目录。已核对 Browser 0.2.2-rc.1、Artifacts 2.10.0 与 2.12.0。脚本在独立临时副本上运行两遍补丁，加载真实已发布 Browser 代码，验证右侧栏 iframe 地址、保存地址、聊天点击、修饰键新标签页、本机模式，以及第三方插件 `lib/` 外的文件逐字节未变。HTTP 测试使用操作系统分配的临时端口，不占用工作区服务或固定宿主机端口。

## 线上验收（伙伴助理执行）

1. 在测试账号容器运行只监听本机的 `python3 -m http.server 4710 --bind 127.0.0.1`。从聊天点对应链接，原生右侧栏显示网页；新标签页也显示同一内容。
2. 同时打开第二个端口，确认各自路径、Cookie 和编辑内容不串。测试带查询、fragment、绝对静态资源路径与重定向的页面。
3. 用 baoyu claude-slides 打开已有测试演示稿，完成一次编辑与保存，确认 WebSocket/SSE 实时同步。测试 Artifacts 入口以及原生 Browser 地址栏。
4. 另一个账号访问复制的实际预览域地址，以及在另一浏览器打开兑换链接，均应拒绝。未登录用户只能进入主站登录，不可读编辑器。兄弟预览来源不能读取主站接口或另一端口。
5. 验证 3080、3090、3091、3092 以及低端口被拒绝；从其他工作区直连转发器，即使猜中目标端口也应拒绝。
6. 验证 Cookie 10 分钟续期、空闲后重新核对登录、网关及测试容器重启后恢复。通过真实桌面本机模式打开已有本机服务，确认不经预览转发。

本地协议及发布包检查不能代替通配符证书、公司浏览器 Cookie 策略、真实编辑器保存和桌面应用的线上验收。回退时移除 `PREVIEW_HOST` 并重建网关，必要时回退测试容器镜像；不删除用户数据或服务文件。
