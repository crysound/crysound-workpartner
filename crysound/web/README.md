# 网页容器的公司配置

公司配置不进入网页镜像。服务器维护 `PARTNER_CONFIG` 目录，网关与每人容器都把它只读挂到 `/opt/partner-config`；`PARTNER_CONFIG` 是宿主机绝对路径，不是网关内路径。在 `crysound/web/.env` 同时设置 `MAGPIE_BASE_URL`，它必须是网页容器能访问的模型接口地址。桌面版仍从自己的登录网关访问模型。

目录里必须有这七个文件（包含当前市场功能需要的脚本和技能）：`plugins.json`、`partner.patch.yml`、`profile-upgrades.mjs`、`plugin-patches.mjs`、`market-profile.mjs`、`market-npmrc.mjs`、`skills/publish-zhaohua-market/SKILL.md`。从同一提交的 `crysound/config/` 同步，目录应允许容器用户遍历，文件应允许读取。不要放钥匙或个人资料：已开通的同事可以用桌面登录令牌通过 `GET /_zp/config/<文件名>` 读取这七个文件。接口不接受网页登录凭证，不提供写入，不缓存结果，也不提供目录内的其他文件。旧域名也继续提供这个接口。

每次启动按插件清单核对安装版本、执行插件补丁，并刷新公司 `magpie` 提供方的整个块（包括删除不再列出的模型）。个人其他提供方和自己选择的默认模型、推理等级保留；历史默认 GPT 未选等级时仍升级到中。提供方地址使用 `!!js` 从启动环境读取，不再构建时替换地址。非法个人 YAML 或动态的整个 `providers` 表达式无法安全修改时会报错，文件保持原样。

dsh 的 bundle、个人、全局和启动覆盖层按顺序生效，patch 的 `config` 整块替换（见 `packages/boot/app-boot/src/profile.ts` 和 `packages/boot/app-boot/src/config-schema/document.ts`）。旧个人配置会覆盖低优先级的公司层；高优先级的公司层会覆盖个人提供方，并使设置页无法保存该配置（`packages/boot/config-editor/src/index.ts`）。因此在不改上游的约束下，启动时在个人 YAML 的语法树上只替换 `providers.magpie`，保留其他节点、注释及 `!!js` 标签。首次默认值仍只写一次。公司网页搜索条目缺失时会补齐；每次启动按公司配置刷新搜索地址和模型，地址从启动环境读取，其他搜索选项保留。

公司 Sol、Terra 模型在各自条目声明 `input: [text, image]`；dsh-llm-pi-ai 将其传给 pi-ai 的模型能力，未声明的自定义模型默认只接收文本。此声明适用于 `openai-completions`，无需添加 `compat.imageInput`。同步公司配置后，已挂载配置目录的网页容器在空闲时重启刷新个人 profile，不需要重建镜像；支持远端公司配置的桌面版在联网重启后获取，离线仍使用安装包内配置。上线后用测试账号分别选择 Sol、Terra，读取一张含中文字的 PNG 并核对原文，再用兆华动画或兆华设计的静帧完成看图自查；配置检查通过不代表真实模型读图已验收。

桌面版启动时携带现有桌面登录令牌，从模型网关同源地址下载完整的七文件快照，使用独立临时目录，完成本次准备后清理。任何文件下载失败、超时、返回非成功响应或插件清单不合法，整份回退到安装包配置，不混用下载中的半份配置。断网回退可能恢复安装包中的旧插件版本和旧公司模型清单；重新联网并启动后重新取服务器配置。已开始应用后的插件安装失败沿用原有行为：记录日志，下次启动重试；配置刷新失败记日志，桌面壳继续启动。

## 默认自动审查

网页镜像构建执行 `crysound/scripts/patch-web-auto-review.mjs`，逐处唯一匹配固定的 dsh 0.2.2-rc.1 发布模块，重复执行不改变文件，缺失或重复命中则构建失败；所有文件先完成转换，再写入并断开安装硬链接。仅修改网页镜像中的权限 Host、权限浏览器模块和审查插件退出路径，桌面构建不调用它。

没有个人 `permission.config.defaultPreset` 时，网页运行时采用 `auto`；显式保存的其他值继续优先。与工作步骤升级一样以“字段是否存在”区分公司默认与个人选择，但不把 Auto 批量写入个人配置，因此旧用户和新用户即时采用同一个默认，也不需要修改共享配置或迁移标记。设置下拉支持自动审查并显示当前默认，选择其他值照常保存。默认只作用于新会话，已有会话保持当前权限；上游可能复用尚未开始的空会话。

默认 Auto 仅在审查插件注册成功且准入检查通过时启用，不弹逐会话实验确认；手动切换当前会话仍保留上游确认。插件缺失、准入出错或停用时，采用固定的工作区内修改与本人审批，即使个人预设表被定制也不提升权限；缺插件恢复旧 Auto 会话时同样降回该组合。审查请求本身失败仍沿用上游的拒绝执行，不能跳过审查。每次原生工具调用和 PTC 内层调用会额外消耗一次同模型审查请求及其上下文 token，外层 `run_code` 不重复审查。

部署必须重建网页镜像，先升级独立测试账号，再按既有空闲策略升级；本项不要求配置同步、网关重建或桌面发布。回退用保留的旧镜像；降级前检查新设置中显式保存的 `defaultPreset: auto`，在新版设置中改回工作区内修改（或由伙伴助理备份后只改该字段），否则旧运行时会拒绝该默认值。未保存过默认权限的人无配置需要回退；保留个人其他配置与会话日志，不批量覆盖旧备份。

轻量检查：在已有镜像、只读挂载仓库的临时容器中运行 `node --test /repo/crysound/tests/web-auto-review.test.mjs`，覆盖真实权限服务的会话事件、个人设置更新、插件缺失/失败/停用、恢复和未修补的桌面默认。页面截图与可重复的浏览器环境启动方式见 [验收证据](../tests/evidence/issue-88/README.md)。本机不构建镜像或发起付费模型请求；另有基于真实发布运行时的无密钥会话回放，覆盖允许写入、审查拒绝转本人审批及文件结果，使用固定审查输出；实际模型的判断与完整新镜像仍须伙伴助理在测试账号上验收。

## 多步任务的工具效率提示

`profile-upgrades.mjs` 在启动时生成独立的 `crysound-tool-efficiency.mjs` 公司提示模块，并以原生 `insert` 加入个人 profile，重复执行不会重复插入。提示明确将多文件阅读列为原生“只能用单文件读取/搜索工具”偏好的公司例外，优先一次有路径标题、限制总输出的命令；搜索结果已足够时不再逐个重读。文件不在 shell 的执行环境、shell 不可用或需要图片等专用读取器时，继续使用原工具，不能绕过访问限制。已获授权的小脚本一次写完并在写入成功后运行；互不依赖的调用保持同轮并行，需要前置结果或审批的步骤继续分开。它只增加模型指导，不增加工具，也不改变权限或原生工具行为。标准、PTC 等普通角色提示不会覆盖这个独立片段；明确提供完整系统提示的极简或自定义预设仍沿用其原生行为，不强行注入。

部署方式是公司配置：同步同一提交的 `profile-upgrades.mjs` 与 `market-profile.mjs` 后，安排已挂载公司配置的网页容器空闲重启；支持远端公司配置的现有桌面版联网重启即可。生成模块的内容随原有升级脚本传输，未增加下载文件，不要求重建镜像、网关或单独发布插件。离线桌面仍使用包内旧配置，下次桌面发布才包含离线版本。回退时恢复旧升级器和市场脚本，恢复前先备份个人配置，仅移除本项生成的插入条目；其他个人条目与会话保留。

轻量检查：用已有发布运行时设置 `DSH_CLI_ENTRY`，执行 `node --expose-internals --experimental-vm-modules --test crysound/tests/company-config.test.mjs crysound/tests/tool-efficiency.test.mjs`（Node 24）。它实际加载生成模块并组装模型提示，覆盖预设覆盖、停用清理、新老 profile、更新幂等、市场初始化、桌面在线下载与离线回退。配置检查不证明模型按提示选择了调用方式。

离线示例题可用 `node crysound/scripts/tool-efficiency-fixture.mjs <新建的基准目录>` 生成。正式对比使用同一套题，在相同模型、推理等级、预设、权限与插件下，改前改后每类交替各跑三次；所有任务用新会话，保留 18 份完整会话及实际脚本输出。分别记录会话和整条命令耗时、主对话模型请求、辅助模型请求、工具调用、输出 token（按供应商报告，缺失不得填零），核对所有答案和脚本文件，再比较中位数与范围。核对改后实际模型请求含本提示，防止测到未生效配置；记录缓存、失败重试、模型路由和环境差异。读文件要求中位数小于 20 秒且输出 token 明显减少，脚本要求主对话模型调用少一次，简单问答与正确率不得退步；三次结果若波动盖过差异就不能宣称提速。本次隔离实测及剩余上线验收见[证据](../tests/evidence/issue-120/README.md)。

## 联网搜索提速

Claude 服务端搜索尚未启用：固定版运行时会丢失服务端工具块和引用来源，网关透传仍待长期测试账号实测。能力复现、只读网关探针和未验收范围见[核对记录](../tests/evidence/issue-137/README.md)。本 PR 不提供原生搜索开关，不能仅加工具声明后启用；以下公司搜索适配是保留的退路，是否先单独上线由伙伴助理决定。

公司 `tool-web` 配置将 `searchTimeoutMs` 设为 18000、`fetchMaxOutputChars` 设为 40000。启动升级同时刷新新老 profile 的这两个字段，保留其他工具选项。抓取限制包括标题、外部内容提示和截断说明；超限仍明确显示截断。共享公司提示要求搜索正文或来源摘要足够时带现有来源直接回答、不再抓网页，证据足够回答时停止搜索和抓取，仅补充具体证据缺口，并满足任务要求的来源数量；完整系统提示预设仍保持原生行为。

搜索顺序与单次等待由网页镜像中的公司适配负责，见[网页工具说明](web-tools/README.md)。部署要同时同步 `partner.patch.yml`、`profile-upgrades.mjs` 和重建网页镜像；只更新配置不能改变旧镜像的搜索顺序。保留旧镜像及这两个配置文件的副本，先升级长期测试账号，再逐人按既有策略换镜像。支持远端公司配置的桌面版联网重启后获得 Luna 搜索模型、输出上限和提示；网页搜索适配不包含在桌面安装包中，本项不宣称已改变桌面搜索顺序。

回退时恢复旧镜像及两个公司配置文件；旧升级器不会自动撤销已写入的工具字段。由伙伴助理在停止 Host 后只将个人 `tool-web.config` 的这两个字段恢复到升级前的值（原先不存在的只删字段），保留期间新增的个人设置和会话；不要整体覆盖旧 profile 备份。启动后核对实际时限与上限。

上线后复跑原基准的同一组三题，每题改前改后各三次、交替进行，固定 Claude 模型、推理等级、预设和插件，使用新会话。保留完整会话、实际搜索模型日志和每个答案的去重来源 URL；逐题记录总耗时、搜索/抓取次数、上下文及输出 token，并按原基准口径比较中位数，目标下降至少 30%，每个答案来源不少于 5 个。缺少原题或基准记录时先补齐，不能用新题代替同题验收。配置测试仅证明顺序、时限、输出上限与提示生效，不证明实际提速或答案质量；三题实测、镜像构建和上线验收由伙伴助理完成。

## 飞书插件本地归档

飞书插件使用镜像内 `file:/opt/company-plugins/aiwayds-dsh-feishu-0.17.0-crysound.2.tgz`。构建脚本从固定发行地址下载，核对 SHA-512 后才写入镜像。每次安装前，共用的 `plugin-artifacts.mjs repair` 按清单目标版本移出旧飞书发行包的依赖记录：个人 `package.json`、`pnpm-lock.yaml`、已有 `node_modules/.pnpm/lock.yaml` 中的飞书 importer、package 和 snapshot，再由原生 `dsh plugin add` 重新解析新版。支持任意旧版本的 `/opt/company-plugins/` 绝对路径、`company-plugins/` 相对路径及公司下载站远程地址（包括缺失旧校验值的锁文件）；不依赖镜像保留上一版归档。只移出旧发行包的安装记录，保留插件配置、会话、已安装文件和其他依赖；新版归档仍须通过固定 SHA-512 验证。三个文件全部解析成功后才依次原子替换，清单最后写；中断后重跑仍会补装，当前版本重复启动不改文件。

本次必须重建镜像并同步清单，先验证独立测试账号，再逐人空闲时换镜像；不能只更新清单后重启旧镜像。Mac/Windows 下个安装包携带同一校验后的归档，桌面会将共享清单中的网页路径转换为 profile 内的相对文件依赖，并把该目标传给同一个修复脚本。旧桌面包不支持这个本地路径，需随新包更新。

轻量测试使用 Node 24 和已有 yaml：`node --test crysound/tests/plugin-artifacts.test.mjs`；默认从已有 dsh 运行时找 yaml，也可设置 `PARTNER_YAML_PACKAGE` 为已有 yaml 包路径。设置 `PARTNER_FEISHU_ARCHIVE` 为校验过的归档绝对路径后，覆盖桌面复制模板、旧版替换、重复启动、校验失败，从 `lib/types` 目录加载资源，以及含空格和引号的测试路径；不设时跳过需要真实归档的用例。

真实升级检查用同一个临时可写目录挂到旧、新镜像的 `/test`，本检出只读挂到 `/src`，设置 `PARTNER_TEST_ROOT=/test` 并清空 `NODE_OPTIONS`。先在含 crysound.1 归档的旧镜像执行 `node /src/crysound/tests/plugin-install-smoke.mjs seed`，再在只含 crysound.2 的候选镜像执行同一脚本的 `upgrade` 子命令；候选镜像必须包含本提交的 `plugin-artifacts.mjs`，本地预检也可只读覆盖 `/opt/partner/plugin-artifacts.mjs`。脚本用真实 dsh/pnpm 验证旧本地包、旧远程地址有/无校验值、桌面相对包路径，核对新版、两份锁、其他插件及配置保留，重复启动和后续 add/remove，并从实际运行时查询飞书插件处于 active、网页正常响应。测试安装允许联网，限一核、1 GiB，不连接真实飞书账号。镜像 CLI 将 desktop 留给 Electron，因此相对路径检查使用独立自定义 profile；真正桌面准备流程由上述轻量测试覆盖，打包后另跑既有 Mac 首启动冒烟，Windows 仍需在目标系统核对升级。

## 上线顺序

1. 保留旧网关提交、旧镜像标签和公司配置的副本；伙伴助理确认回退位置。以下步骤由伙伴助理在服务器执行，本 PR 不创建服务器目录或改正在使用的容器。
2. 建立 `.env` 的 `PARTNER_CONFIG` 目录，把同一提交的七个配置文件同步进去，设好目录遍历与文件读取权限，并填 `MAGPIE_BASE_URL`。使用完整目录挂载，后续可以原子替换目录内的单个文件；不要把挂载目录本身删除重建或换 inode。
3. 沿用现有市场配置（包括 `MARKET_ADMINS` 和内部注册表设置），先更新网关：`docker compose -f crysound/web/compose.yml config` 核对目录与只读挂载，再 `docker compose -f crysound/web/compose.yml up -d --force-recreate gateway`。核对有效桌面令牌能读七文件，缺失/过期令牌为 401，不在允许列表的文件为 404。旧用户容器此时继续使用原镜像中的配置。
4. 由伙伴助理构建一次新镜像，先用独立测试用户验证完整清单的插件安装与补丁、模型清单和个人提供方保留，再逐人空闲时用 `bin/upgrade-when-idle.sh <代号>` 重建。已有容器必须重建一次才能增加挂载；仅重启旧容器不会增加挂载。命令行开通和重建也读取相同 `.env`。
5. 发布包含本次桌面代码的安装包，分别核对网关可达时的公司配置和断网时的包内回退。本次不触发桌面构建。
6. 以后只变更清单、模型或补丁时，同步七个配置文件（来自同一提交，别在桌面启动下载时发布半份文件），然后安排已挂载目录的个人容器在空闲时重启即可，不需要重新构建镜像。重启前保留个人配置副本；公司 magpie 项会被刷新，其他提供方应保持。系统工具、dsh 或品牌变更仍需要镜像。

## 回退

仅配置有问题时，恢复挂载目录内七个文件的上一份完整副本，再安排空闲重启。新容器挂载路径不变。恢复旧模型配置前须确认旧默认模型仍可用；启动升级不会替用户改掉已经选定的模型。

需要回退代码时，先把新容器按空闲策略重建为保留的旧镜像（它自带旧配置），再把网关切回旧提交并重建。已写入的公司提供方要恢复到旧清单时，应先用修正后的挂载配置启动刷新，或者在旧版本重建前恢复此前备份的个人配置；不要用较早个人配置覆盖用户在此期间新增的提供方。新桌面版连接旧网关拿不到接口时会回退安装包配置。网关签名密钥与个人数据不作变更。

## 网页按问题摘要

网页镜像的公司补丁给 `web_fetch` 增加可选 `prompt`：填明问题后，先由公司配置的小模型提炼证据、保留关键原句和数字，只把带原 URL 的摘要交给主模型。默认开启，使用现有公司网关和 DeepSeek flash；没填问题、辅助模型失败或 15 秒内未完成时，继续返回原来的截断原文。公司联网提示要求遇到 403、登录或反爬时换来源，不写脚本绕过。配置字段、请求日志、测试、镜像与共享配置部署，以及 `fetchSummary: false` 的回退办法见[网页工具说明](web-tools/README.md#按问题摘要)。伙伴助理需在测试账号用 #137 原三题对比上下文峰值、主模型生成时间和总耗时，逐题保证不少于五个答案来源；本地无密钥测试不证明实际提速。
