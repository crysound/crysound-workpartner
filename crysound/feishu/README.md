# 飞书授权设置

应用内入口由 `native/client.js` 注册为原生设置页，按钮和导航图标使用 dsh 组件，行布局使用 dsh 主题变量。`brand.js` 不再添加链接。旧 `/_zp/feishu/` 地址保留独立页面，兼容书签。

`prepareSkillProfile` 在网页版和桌面版的既有启动准备流程中安装随包模块，不联网下载。模块副本及 `file:company-plugins/feishu-settings` 依赖属于个人 profile，已有个人配置和依赖保留。重复启动会修复被依赖安装移除的模块副本。模块使用设置壳公开 ledger 中的共享 store 打开指定页，升级 dsh 时应复核 `sidebar.settings` 的 `store.create().actions.openSection`。

网页版在点击时预开小窗，避免等待网络后被拦截；拦截后尝试新标签页，并提供可手动点击的链接。飞书内置浏览器直接走同页授权，OAuth state 只记录 popup / redirect 两种固定回跳模式，不接受外部回跳地址。小窗成功回调仅通知同源 opener，随后关闭；无 opener 时回到应用并打开设置。设备码授权保存未完成的轮询时间，回到应用或重新打开设置时继续；飞书项目的外部授权站没有应用回跳地址，需要完成后手动返回。

桌面版设置通过既有 `dsh-app://app` 协议调用主进程。主进程沿用 `desktop-status`、`desktop-disconnect`，飞书项目沿用本机 CLI 和 `desktop-config` 生成的配置。授权使用隔离子窗口和现有登录分区；主页面打开时、获得焦点时、授权小窗关闭时及授权期间自动刷新。旧的本机独立页面继续可用。

飞书新授权记录增加不含凭据的 `authorizedAt` 元数据，自动换令牌保持原时间。旧记录不补猜时间。姓名来自既有本人名单，不增加飞书权限。飞书项目固定版本的 [CLI 状态输出](https://github.com/larksuite/meegle-cli/blob/51b6c92fe7bab9f830db9f4bbf2739927c434815/internal/products/meegle/commands/auth.go#L504)只包含连接状态、主机及剩余有效期，不包含姓名或授权时间；适配接口将剩余分钟数传给原生设置，已连接时显示“已连接 · 还剩 N 天有效”（按完整天数计算），不足一天显示“已连接 · 还剩不到 1 天有效”。上游命令不提供授权时间，不为项目新增时间记录；上游未返回有效期时只显示“已连接”。飞书主行仍显示姓名和授权时间。界面已获审阅通过，真实授权流程由伙伴助理验收。

## 部署及测试账号验收

界面已获负责人审阅通过，由伙伴助理同步公司配置中的 `plugin-patches.mjs`（显式打开设置时暂缓首次引导，避免回跳设置页被关闭），再重启网关、重建镜像并等待个人容器空闲时更新，同时重新构建发布桌面版。只替换品牌脚本不能启用原生模块。

1. 使用专用测试账号登录。不要使用同事已有授权做断开测试。进入设置 → 飞书授权，核对导航有链接图标、无下划线，只有选中项高亮。切换通用设置后应取消飞书授权的高亮。
2. 网页宽屏和窄屏、浅色和深色分别核对未连接、已连接两种状态。点击连接，应用页面保持设置打开；提供方授权完成后小窗关闭，状态自动变成已连接，显示本人姓名和授权时间。重新授权后时间更新。飞书项目改为核对命令返回的剩余有效期（含不足一天），上游命令不提供授权时间。点断开后先确认，再核实状态变为未连接且命令无法再领取令牌。
3. 阻止弹窗，核对新标签页或手动链接和“完成后回到这里”提示。取消授权或关窗，原设置仍可操作；状态接口失败时显示无法核实，不冒充未连接。另测远端撤销失败后的待撤销状态。
4. 在手机和平板的飞书内置浏览器用同一测试账号连接，核对同页授权、回到应用后自动打开飞书授权设置、状态已连接。飞书项目设备码授权完成后返回应用，核对继续轮询直至已连接；分别测试中途关闭设置和重新打开。
5. 桌面安装测试构建，核对授权子窗口、主设置留在原处、成功后自动刷新；本机飞书项目和云端各自隔离。确认桌面页面网络响应没有本人登录令牌或长期飞书凭据。验证已有 `desktop-config` 和旧书签入口仍可用。
6. 以上场景补齐真实截图并记录构建版本。预览截图和模拟桌面测试不算此步骤通过。
