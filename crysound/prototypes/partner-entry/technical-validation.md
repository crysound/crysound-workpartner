# 伙伴入口技术验证

核对日期：2026-11-07（北京时间）。源码基线：`bfea7137347fea92fd936935014ea0a7310ddaaf`。本单只提供独立原型、源码核查和已有网页上的临时只读验证，不改变线上行为。

## 结论

固定入口可实现，但现有品牌插槽不能直接承担“打开主对话”的职责。上下文压缩已有完整机制，长期复用会话在架构上可行；压缩不等于历史加载成本固定，不能承诺聊几周仍无性能退化。新网页可以访问同一后端的已有会话；“伙伴对应哪条会话”仍需服务端明确保存。当前桌面版启动本机 Host，同一飞书登录不等于使用网页容器，不能直接找回网页主对话。

建议先评审原型。方向通过后先补入口扩展点、本人主对话绑定和长期会话验证，再做正式功能。桌面端跨设备一致性需要另行接入相同后端，不能仅在浏览器里记住会话编号。

| 问题 | 本轮依据 | 判断／边界 |
| --- | --- | --- |
| 顶部能否出现稳定入口 | 真实网页临时注入；四次收起／展开、打开已有会话后均保持一个顶部节点，见 [live-browser.json](evidence/live-browser.json) | 当前版本可行；临时 DOM 验证不构成对以后上游更新的稳定承诺 |
| 能否直接复用品牌行点击 | 源码及真实网页均显示品牌行是 New session；折叠品牌在展开按钮内部 | 不能只换图片和文字；必须新增独立伙伴动作，避免误建会话或把伙伴点击变成展开侧栏 |
| 上百轮上下文压缩 | 已配置 `compaction-basic` 和 `/compact`；自动压力检查、溢出恢复、摘要和检查点机制都存在 | 机制可用；本轮没有进行真实模型的百轮连续调用，摘要质量和多轮压缩后的事实保真尚未验收 |
| 历史加载是否越来越慢 | 前端首次拉尾页，向前分页；持久层冷读有全量读入／解码路径及缓存 | 热切换可受益于分页／缓存；冷启动仍随日志增长，不可把上下文压缩当作磁盘历史压缩 |
| 新开网页能否找回 | 同一已登录浏览器的新标签页能够找到同一条已有会话 | 证明已有会话属于后端；不证明全新浏览器已登录，也不证明已有“固定伙伴”绑定 |
| 桌面版能否找回网页主对话 | `main.ts` 创建 `DesktopHostProcess` 并连接其 Host；公司登录提供身份与模型网关 | 当前代码没有自动连接本人网页容器的主对话；不能宣称跨端一致已经具备 |

## 入口与运行状态

源码入口：[SidebarRoot.tsx](../../../packages/client/ui-sidebar/src/client/SidebarRoot.tsx)、[slots.ts](../../../packages/client/ui-sidebar/src/client/contract/slots.ts)。

`sidebar.brand.mark` 和 `sidebar.brand.name` 是品牌子插槽，不拥有导航动作。`sidebar.panellist` 能注册面板入口，但位于“新建会话”之后，不满足最上方固定入口的布局。当前没有同时覆盖顶部独立按钮、折叠轨道和手机布局的专用伙伴入口扩展点。

正式实现宜只给侧栏补一个明确的顶部入口扩展点，由公司插件提供内容和动作；避免替换整个侧栏、依赖翻译文字、依赖样式哈希或在 React 管理的节点中长期插入外部节点。macOS 标题栏拖动、Windows 顶栏和手机抽屉需各自验收。

本轮临时节点只证明该版本布局可以容纳入口，临时观察器在验证后已断开并移除节点。原型的状态由演示控件驱动，并非线上运行状态验收。现有 [pet.js](../../brand/pet.js) 的适配器观察的是**当前打开的会话**；正式伙伴头像应订阅伙伴主会话的运行、待确认和完成事件，即使人在看另一个任务也要保持正确。不能直接沿用“当前页面”的状态推断。

## 长期会话：压缩与历史加载是两条路径

压缩依据：

- [基础组合](../../../packages/bundle/base/cordis.patch.yml) 和 [网页标准预设](../../../packages/bundle/web-app/presets/standard.patch.yml) 已挂载压缩及手动压缩命令。
- [compaction-basic/index.ts](../../../packages/compaction/compaction-basic/src/index.ts) 在步骤前检查压力，并处理切模型和上下文溢出恢复。
- [config.ts](../../../packages/compaction/compaction-basic/src/config.ts) 按模型窗口、输出预留及摘要空间解析预算，不按“聊了几天”轮换会话。
- [region.ts](../../../packages/compaction/compaction-basic/src/region.ts) 追加摘要、检查点和被遮蔽记录的来源；已有 [真实循环回归用例](../../../packages/compaction/compaction-basic/tests/compaction-loop-repro.spec.ts) 覆盖再次压缩检查点。此处是源码依据，**本轮没有运行该测试**。

加载依据：

- [客户端 session.ts](../../../packages/api/session-controller/src/client/sessions/session.ts) 的 `open()` 拉取尾页，`loadOlder()` 按轮次向前分页，普通页以 50 条消息和两轮为下限，500 条消息为上限。
- [history/controller.ts](../../../packages/api/session-controller/src/history/controller.ts) 提供按会话地址和窗口读取的接口。
- [持久层 index.ts](../../../packages/session/session-persistence-jsonl/src/index.ts) 的 `readStoredLog()` 在缓存未命中时读取并解码日志；[generation.ts](../../../packages/session/session-persistence-jsonl/src/generation.ts) 的稳定读取会读完整文件。摘要没有删掉完整历史，因此冷读耗时和内存仍可能随记录体量增加。

这里的页大小是代码参数，不是实测性能结果。本轮没有报告毫秒值，也没有把本地原型、暖缓存或空日志测量当成产品性能。几周自然时间本身不是限制，真正影响包括记录字节数、工具输出大小、附件、压缩次数和冷／热状态。

正式实现前的验证门槛：用隔离测试会话覆盖 100／300 轮、长工具输出、附件和多次压缩；确认最早指定的事实在压缩后仍能正确使用，所有原记录能翻查；分别测新浏览器页面首次打开、热切换、服务重启后的冷读和向前翻页，记录重复运行的范围、日志体量和读入／解码／传输／渲染耗时。若冷读超出可接受范围，再评估索引或分段读取。不能在未测前承诺恒定速度。本轮不为该验证生成付费模型调用。

## 找回同一条主对话

当前选择保存在 [navigation.ts](../../../packages/client/ui-workspace/src/client/navigation.ts) 的 `dsh.sessions.current`，这是浏览器存储，不是用户的永久主对话绑定。网页会话本身可以从同一后端重新列出；本轮确认过同一浏览器新标签页可以找到所选的已有会话，没有新建或发送内容。

正式绑定应在本人后端保存一个明确的主会话引用，以登录身份和后端为边界；新窗口或浏览器从服务端读取。首次创建要处理同时打开多个窗口，避免建出两条；找不到原会话时明确提示，不能悄悄换成新会话。主会话从普通列表的展示中去重，但普通任务的排序和归属保持原有逻辑。这个引用的结构变更需要评审，本单没有写入用户数据。

桌面依据：[main.ts](../../../apps/desktop/src/main.ts)、[公司登录适配](../../../apps/desktop/src/crysound/partner.ts)。当前启动本机 Host，公司登录发放模型网关凭据；没有因此共享网页容器内的会话文件。若产品要求网页和桌面都回到同一伙伴，需要桌面连接本人云端会话服务，并明确本机模式的语义、断线和登录过期处理。本轮不实现该架构变更。

## 本轮验收与剩余项

已完成：可点击原型、四种截图、五状态实际品牌组件、普通任务返回主对话、发送／确认演示、刷新恢复本地示例、窄屏无横向溢出、减少动态效果状态文字、源码核查、真实网页临时注入和同浏览器新标签页已有会话可见性检查。

未验收：正式入口插件、多周／百轮真实模型会话、摘要事实保真、冷／热加载性能、全新浏览器身份登录与服务端主会话绑定、桌面跨端找回。上述结论足够判断实现路径和风险，不能作为正式功能上线通过的依据。本单只提交原型供方向评审，需评审通过后再决定实施范围。
