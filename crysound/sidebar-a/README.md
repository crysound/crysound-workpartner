# 侧栏方案 A：正式实现与交付

固定顺序为新对话 / 搜索 / 作品 / 自动化 / 市场（插件·技能）/ 插件入口 / 最近对话。原型保留在草稿 PR #130，仅供参考，不合入；本目录记录正式包补丁和验收。正式实现不包含原型文件。

## 行为

- 新对话下一行“搜索”就地变成输入框，结果替换最近对话列表；清空、删除最后一个字符或 Esc 收回原行。输入框仍由工作区组件拥有，经 React portal 渲染到侧栏通过 owner props 传入的行容器，焦点和图标位置不因展开变化。搜索与快捷键使用同一个控制器；保留内容搜索、分页、归档结果及定位。收起状态搜索会展开侧栏；手机沿用抽屉、焦点限制和 Esc。macOS 隐藏侧栏时窗口顶部仍有搜索；Windows 收起时为搜索预留菜单空间。
- 作品的稳定面板 id 为 `baoyu-design.artifacts`，自动化为 `schedules`，市场为 `plugins`。只呈现已有注册，不伪造打不开的入口；缺少固定入口时提示去设置或市场启用。“我的工作台”仍是个人插件，不并入作品或账号菜单。
- 其他插件按显示名称的中文拼音排序，同名用所属插件标识作 Unicode 后备键；同插件多入口再按 `order`、同值注册顺序排列。归属使用现有注册账本的 `registrant`，显示名称从只读插件清单解析；无清单权限或元数据时用该插件已有入口名称。插件排序不增加安装时间或安装记录。0 个无占位，1–2 个直显，3 个及以上全部进入更多，菜单保留活动项和原面板打开回调。
- 工作区数量不超过一个时默认平铺（含无归属会话），多个时默认分组。手动选择后，刷新、重新挂载和工作区数量变化都保留所选视图。显示选项保留分组、排序、归档筛选和新建；一个工作区时可从这里管理原工作区，不迁移会话归属。
- 在原有本机偏好 `dsh.workspace.view.v5` 内增加可选 `groupByExplicit`，手选时写 `true`；`false` 表示清除手选意图、回到自动。缺省时兼容旧 `flat` / `workspace-tree` 为手选；旧 `workspace` 无法区分默认与手选，一律按自动处理。此字段不进入会话、工作区或插件安装记录，不新增存储位置或服务端数据。
- 新对话改为普通行，保留创建权限检查。分组视图默认展示量由 5 提高到 12，保留活动会话提升、展开其余、搜索定位；平铺沿用原有完整滚动列表。桌面会话行仍为 32px，手机为 40px。账号菜单下载沿用已完成的 #131，桌面隐藏。

## 共享发布路径

`patch-sidebar.mjs <runtime node_modules>` 只接受两个包都为 `0.2.2-rc.1`；替换必须各唯一命中，否则抛错。在任何写入之前准备两个模块，重复执行字节不变；写入时断开硬链接，保留权限。可接在已有市场补丁之后，不修改其他市场行为。导航补丁为 v2、工作区补丁为 v3，可从原始包或已合入的精确前序产物升级；未知前序仍立即失败。

网页版在 Dockerfile 安装固定 dsh 及市场修补后运行；桌面在 `prepare-dsh.ts` 物化运行时后、生成完整性记录前运行。两边消费同一份补丁和品牌 CSS。单改源 TSX 或网关无法发布本改动。

**发布依赖：必须与 #133“兆华柔和”皮肤合到同一次伙伴镜像更新，不单独换线上镜像。** 皮肤实现 PR #134 已合入主分支，本分支已接入；皮肤负责外观，侧栏负责结构，皮肤的新对话行适配为桌面 32px、手机至少 40px。已复核双方的 `brand.css`、Dockerfile、桌面准备脚本以及收起控件的选择器。皮肤首次进入默认柔和；设备已明确选过经典（存储值 `default`）时保留原选择。设置文案为“兆华柔和（默认）/ 经典”。

由伙伴助理重建伙伴镜像、按既定策略更新容器；桌面随下一安装包生效。本 PR 不触发构建、不改工作流、不动线上容器。回退时使用上一镜像和上一桌面安装包；本改动没有用户数据迁移，原分组和会话不需要回填。不要直接在共享包存储或运行中容器里改文件。

脚本只在该标签页用浏览器响应替换预览本分支的两个模块及品牌 CSS，并加入本分支皮肤样式表；业务接口仍来自现有真实服务器。不更改服务器或安装包，不写业务数据，不运行模型回合。截图仅截侧栏，姓名和真实会话标题用外观遮罩替换。皮肤切换只改当前页面属性；视图偏好的读写隔离到该标签页的临时会话存储，刷新检查不会覆盖本人已有偏好。它不是本分支完整构建的服务，也不是 Electron；因此本轮没有提供符合真实构建和模型回合条件的 GIF。

## 视图偏好修复复核（11-07）
